02Windows · terminal e comandos do agente

Passo 1 · Escolha o terminal padrão

O agente roda os comandos no primeiro perfil de terminal disponível. No Windows, isso costuma ser o PowerShell. Se o seu projeto usa comandos de Linux (por exemplo, scripts .sh), prefira o Git Bash ou o WSL.

1
Paleta (Ctrl + Shift + P) › Terminal: Select Default Profile.
2
Escolha PowerShell, Git Bash (aparece se o Git for Windows estiver instalado), Command Prompt ou uma distribuição do WSL.
3
Abra um terminal novo (Ctrl + `) e confira se abriu o escolhido.

Passo 2 · Defina o Run Mode com cuidado

A documentação do Cursor descreve a sandbox de comandos só para macOS e Linux. No Windows, trate os comandos do agente como execução direta na sua máquina:

  • Cursor Settings › Agents › Approvals & Execution: mantenha Auto-review (padrão) ou use Allowlist se quiser aprovar mais coisas à mão
  • Evite Run Everything fora de máquinas ou pastas descartáveis
  • Se usar WSL, abra o projeto dentro do WSL para os comandos rodarem lá

03Linux · sandbox dos comandos do agente

No Linux, o Cursor isola os comandos do agente com Landlock (arquivos) e seccomp (chamadas de sistema). Requisitos:

  • Kernel 6.2 ou mais novo, com Landlock v3
  • User namespaces sem privilégio habilitados
# Versão do kernel (precisa ser 6.2 ou maior) uname -r # Landlock ativo no kernel? (deve aparecer "landlock" na lista) cat /sys/kernel/security/lsm
Se o kernel não atender, o Cursor não falha: ele passa a pedir sua aprovação antes de rodar comandos. A instalação desktop já traz o perfil AppArmor necessário; só o CLI avulso e ambientes remotos podem precisar do pacote cursor-sandbox-apparmor (ver a documentação de Run Modes).
Dentro da sandbox, id -u mostra 0 (root dentro de um namespace isolado), não o seu usuário. Scripts que precisam do seu UID real devem ler CURSOR_ORIG_UID e CURSOR_ORIG_GID.

Terminal padrão

Paleta › Terminal: Select Default Profile › bash, zsh ou fish. Use o mesmo shell do seu dia a dia, para o agente encontrar as mesmas ferramentas (node, python, docker...).

03Linux · prompt, fontes e arquivos

Prompts pesados atrapalham o agente

Temas como Powerlevel10k podem embaralhar a saída que o agente lê. O Cursor define a variável CURSOR_AGENT nas sessões dele; use-a para simplificar o prompt só nessas horas:

# ~/.bashrc · prompt simples quando o Cursor roda o terminal if [[ -n "$CURSOR_AGENT" ]]; then PS1='\u@\h \W \$ ' fi

Fontes

# Exemplo no Ubuntu/Debian: instalar a Fira Code sudo apt install fonts-firacode # depois, em Settings › Font Family: 'Fira Code', e Font Ligatures: true

Onde ficam os arquivos no Linux

Configurações do editor (settings.json)~/.config/Cursor/User/settings.json
Configurações do Cursor e do agente~/.cursor/ (permissions.json, sandbox.json, mcp.json)
Configuração do CLI~/.cursor/cli-config.json (ou $XDG_CONFIG_HOME/cursor/cli-config.json)

O caminho ~/.config/Cursor/User segue o padrão herdado do VS Code. Atalho: paleta › Preferences: Open User Settings (JSON).

05Ajustes comuns, passo a passo (todos)

A · Cursor Settings › General

  • VS Code Import (em Account): se você usava o VS Code, clique em Import para trazer extensões, temas, configurações e atalhos
  • Privacy Mode: ligado, para seu código não ser usado em treinamento (nas equipes, já vem ligado)
  • Canal de atualização: Stable (Early Access traz prévias menos estáveis)

B · Cursor Settings › Models

  • Modelo padrão: Auto para começar (detalhes na próxima aula, "Models e Rules")
  • Chave de API própria (opcional): cole a chave do provedor e clique em Save

C · Cursor Settings › Agents › Approvals & Execution

  • Auto-review (padrão): lista de permitidos + sandbox (macOS/Linux) + classificador
  • Quer aprovar sempre um tipo de comando? Peça ao agente: "quero aprovar todo comando de deploy"; ele ajusta o permissions.json

D · Cursor Settings › Tab

  • Deixe o Tab ligado; desligue só para tipos de arquivo em que atrapalha (ex.: Markdown)
  • O indicador Cursor Tab no canto inferior direito pausa ou desliga rapidamente

E · Cursor Settings › Indexing e Network

  • Hierarchical Cursor Ignore (Indexing › Ignore Files): procura .cursorignore nas pastas acima do projeto
  • Network › Run Diagnostics se a IA falhar; HTTP Compatibility Mode = HTTP/1.1 atrás de proxy corporativo

G · Idioma

  • Interface em português: instale a extensão Portuguese (Brazil) Language Pack (Ctrl/Cmd + Shift + X), depois paleta › Configure Display Language › pt-br e reinicie. Os menus próprios do Cursor podem continuar em inglês
  • Respostas da IA em português: crie uma User Rule "Responda sempre em português do Brasil" (barra lateral › Customize › Rules; ela sincroniza com a sua conta)

H · Arquivos que a IA não deve ler

  • No projeto: .cursorignore na raiz, com a mesma sintaxe do .gitignore
  • Em todos os projetos: a lista global de ignorados (vem vazia). Sugestões da documentação: **/.env, **/.env.*, **/credentials.json, **/secrets.json, **/*.key, **/*.pem, **/id_rsa
  • Já ignorados por padrão: o .gitignore, arquivos de lock, .env*, .git/ e vários binários e documentos (PDF, planilhas)
O .cursorignore bloqueia o Agent, o Tab, o Ctrl+K e as menções com @, mas não o terminal nem as ferramentas MCP. Segredo de verdade não fica no projeto.

07Levar a configuração para outra máquina

Do VS Code para o Cursor

Um clique em VS Code Import (seção 05-A) resolve na mesma máquina.

Entre máquinas: perfis

1
Na máquina de origem (VS Code ou Cursor): paleta › Preferences: Open Profiles (UI).
2
No perfil, menu de três pontos › Export Profile, para um arquivo ou um GitHub Gist.
3
Na máquina de destino, no Cursor: Preferences: Open Profiles (UI) › seta ao lado de New Profile › Import Profile.
4
Cole a URL do Gist ou escolha o arquivo, clique em Import e ative o perfil (ícone de visto).
Perfis levam as configurações do editor. Os arquivos de ~/.cursor (permissões, MCP, CLI) e as rules pessoais você copia à mão ou recria. Cuidado para não levar chaves de API em arquivos compartilhados.

08Problemas comuns e checklist final

ProblemaSistemaSolução
O agente pede aprovação para todo comandoLinuxKernel abaixo de 6.2 ou sem Landlock: a sandbox não sobe e o Cursor pede aprovação. Atualize o kernel ou use a Allowlist
Saída do terminal cortada ou bagunçadaLinux, macOSPrompt pesado (Powerlevel10k): use a variável CURSOR_AGENT para simplificar
Comandos de Linux falham no agenteWindowsO terminal padrão é PowerShell: troque para Git Bash ou abra o projeto no WSL
Arquivos aparecem todos modificados no GitWindowsFim de linha CRLF × LF: ajuste files.eol e a configuração core.autocrlf do Git
Não acho o settings.jsonTodosPaleta › Preferences: Open User Settings (JSON)
A IA não responde na rede da empresaTodosNetwork › HTTP/1.1 e Run Diagnostics; peça à TI os domínios liberados
Respostas em inglêsTodosUser Rule pedindo português do Brasil, ou escreva o pedido em português

Checklist final

  • Terminal padrão escolhido e testado
  • Run Mode em Auto-review; sandbox ativa (macOS, Linux 6.2+) ou aprovações conferidas (Windows)
  • VS Code importado (se usava) e Privacy Mode ligado
  • Modelo em Auto e canal Stable
  • Fonte, tema e formatação ao salvar do seu jeito
  • Lista global de ignorados com .env, chaves e credenciais
  • User Rule de idioma criada
  • Você sabe onde ficam o settings.json e a pasta ~/.cursor
