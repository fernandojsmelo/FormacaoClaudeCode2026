Overview
da IDE

A Antigravity IDE é o editor de código do Antigravity: um ambiente de desenvolvimento em que os agentes trabalham no editor, no terminal e no navegador, ao lado de você. Nesta aula, percorremos a tela peça por peça: explorer, editor, terminal e o painel do agente. Vemos também os recursos de Tab (Supercomplete, Tab-to-Jump e Tab-to-Import), os task groups, a revisão de mudanças, o navegador com suas proteções, as personalizações e quando usar a IDE ou o Antigravity 2.0.

Conceito01

O que é a Antigravity IDE

Segundo a documentação, é um ambiente de desenvolvimento agêntico feito para a era "agente primeiro": integra agentes ao seu espaço de trabalho e lhes dá ferramentas para operar sozinhos no editor, no terminal e no navegador, com ênfase em verificação, tarefas e Artifacts.

IDE com IA

Tudo o que se espera de um editor moderno, mais o Agent e o Tab, a completação inteligente.

Agentes assíncronos

Agentes locais que trabalham em paralelo, em todos os seus workspaces.

Agente de navegador

Usa o Chrome para você: testar interfaces, ler painéis, fazer ações em sites de desenvolvimento.

A IDE não é suportada para clientes enterprise. Em empresas, use o Antigravity 2.0 ou o CLI.
Para quem vem do VS Code ou do Cursor, a interface é familiar, e na primeira abertura dá para importar configurações, extensões e temas (aula 03).

Editor03

Tab: a IA enquanto você digita

Supercomplete

Sugere código perto do cursor e pode mudar o arquivo inteiro de uma vez, como renomear uma variável em vários lugares ou ajustar funções relacionadas. Tab aceita.

Tab-to-Jump

Sugere o próximo lugar lógico para editar. Aparece um ícone "Tab to jump"; Tab leva o cursor até lá.

Tab-to-Import

Você digitou uma função ou classe que não foi importada? Tab completa a palavra e adiciona o import no topo do arquivo.

ConfiguraçãoO que faz
Ligar e desligarAutocomplete, Tab-to-Jump, Supercomplete e Tab-to-Import, cada um separado
Tab speedSlow (espera mais contexto), Default ou Fast (sugestões rápidas)
Highlight inserted textDestaca o que entrou por Tab, para você acompanhar
Clipboard contextUsa o que está na área de transferência para sugerir melhor
Allow gitignored filesLiga o Tab em arquivos listados no .gitignore (por padrão, ficam de fora quando há Git)
Agente04

O painel do agente

O painel à direita é onde você trabalha com o agente. A documentação descreve o agente como um sistema de raciocínio em várias etapas, movido por um modelo de ponta, que raciocina sobre o seu código, usa muitas ferramentas (inclusive o navegador) e se comunica por tarefas e Artifacts.

  • Começar novas conversas, inclusive várias em paralelo
  • Anexar imagens (um print do erro, um esboço da tela)
  • Trocar o modo do agente e o modelo
  • Acompanhar, na barra inferior, arquivos alterados, processos no terminal e Artifacts
Componente do agentePara que serve
Modelo de raciocínioO "cérebro": Gemini, Claude ou GPT-OSS, conforme o plano
FerramentasLer e editar arquivos, terminal, navegador, MCP
ArtifactsPlanos, diffs, diagramas, imagens, gravações
ConhecimentoO que o agente guarda para tarefas futuras
Para apagar uma conversa: ícone de lixeira no painel do agente.
Agente05

Planejar ou executar direto?

ModoComo o agente trabalhaUse para
PlanningPesquisa o código, organiza o trabalho em task groups e gera um plano de implementação antes de mexerFuncionalidades, refatorações, mudanças em vários arquivos
FastExecuta direto, sem fase de planejamentoRenomear uma variável, rodar um comando, pequenos ajustes
Política de revisão

No Planning, a política Request review faz o agente parar e esperar sua aprovação a cada plano ou diff. Always proceed segue sem parar.

Regra prática: se a tarefa cabe numa frase e num arquivo, Fast. Se você precisaria pensar antes de fazer à mão, Planning com revisão.

Navegador07

O agente no navegador

O Antigravity pode abrir, ler e agir num Chrome local por meio de um subagente de navegador: testa o site que você está desenvolvendo, lê documentação e automatiza tarefas no navegador.

  • Captura telas e grava vídeos das ações, salvos como Artifacts
  • A gravação aparece no passo do navegador, em loop, para você revisar
  • Dá para desligar tudo em Settings › Browser › Browser Tools
Perfil separado do Chrome

O agente usa um perfil próprio, sem os cookies e logins do seu perfil normal. Os logins feitos nesse perfil ficam salvos para a próxima vez. A pasta do perfil pode ser mudada nas configurações de Browser.

Logins feitos no perfil do agente persistem. Só entre nele com contas de teste, nunca com banco, e-mail pessoal ou administração de sistemas.
Segurança08

Allowlist e denylist

CamadaComo funciona
DenylistBloqueia URLs perigosas ou maliciosas, consultando um serviço do Google a cada navegação. Se o serviço estiver fora do ar, o acesso é negado por padrão
AllowlistUm arquivo de texto local com os sites em que você confia. Começa só com localhost
Quando o site não está na allowlist

O navegador pergunta e oferece Always allow. Clicar adiciona o endereço à allowlist. Também dá para editar a lista à mão.

A denylist sempre vence: não dá para liberar um endereço que está nela.
É o mesmo princípio de menor permissão do curso: o agente começa podendo ver só o seu servidor local, e você amplia aos poucos.
Personalizar09

Rules, workflows, skills e MCP

Onde fica

Menu … no topo do painel do agente › Customizations: rules, workflows e skills; e MCP Servers para a MCP Store.

RecursoPara quê
RulesContexto permanente: convenções, estilo, restrições
WorkflowsUma sequência de passos em Markdown, chamada com /nome-do-workflow
SkillsPacotes de conhecimento com SKILL.md (padrão aberto)
MCP StoreInstala servidores MCP com um clique
Workflows estão sendo descontinuados em favor de skills até 01/11/2026. Para migrar os seus, use /migrate-workflows no chat ou o guia oficial de migração.
Workflows, enquanto existirem

Globais (+ Global) ou do workspace (+ Workspace); até 12.000 caracteres cada; um workflow pode chamar outro.

Rules dão contexto (no nível do prompt); workflows e skills dão procedimento (no nível da trajetória).

Outros editores11

Antigravity no seu editor favorito

As extensões do Antigravity levam os agentes para outros editores, com painel de conversa, diffs inline e planos interativos, sem trocar de ambiente.

Visual Studio Code

Para quem já tem o VS Code configurado do jeito que gosta.

Visual Studio e JetBrains

Para equipes de .NET, Java, Kotlin e Python nas IDEs da JetBrains.

Zed e Xcode

Zed para quem busca leveza; Xcode para apps da Apple (macOS, iOS, iPadOS, watchOS, visionOS).

A conta é a mesma em todas as superfícies: o login define os modelos, as cotas e a política de dados, seja na IDE, numa extensão, no CLI ou no 2.0.
Na prática12

Uma sessão de trabalho típica

1 · AbrirA pasta do projeto (com Git e um AGENTS.md).
2 · PedirNo painel, em Planning, com o objetivo e o critério de pronto.
3 · Revisar o planoComentar no Artifact; aprovar.
4 · AcompanharTask groups, pendências, terminal e navegador.
5 · Revisar e commitarReview Changes, testes, commit.
Enquanto o agente trabalha

Use o editor normalmente, com o Tab, em outra parte do código. É o "par de mãos extra".

Armadilhas13

Erros comuns na IDE

Aceitar pendências sem ler. "Accept all" num comando que você não entendeu é como rodar o comando de olhos fechados.
Logar contas pessoais no perfil do agente. Os logins persistem.
Liberar sites demais na allowlist. Cada "Always allow" amplia o que o agente pode acessar.
Criar workflows novos agora. Eles serão descontinuados; escreva skills.
Planning para tudo. Para tarefas mínimas, o Fast é mais rápido e gasta menos cota.
Usar a IDE na empresa. Ela não é suportada para enterprise; use o 2.0 ou o CLI.
