Modo02

Debug Mode: evidência em vez de palpite

Para bugs que você reproduz mas não entende. Em vez de sair escrevendo correções, o agente levanta hipóteses, instrumenta o código e usa dados reais de execução.

1 · HipótesesExplora os arquivos e lista causas possíveis
2 · LogsAdiciona registros que vão para um servidor local de debug
3 · ReproduzirPede que você repita os passos do bug
4 · AnalisarLê os logs e acha a causa real
5 · CorrigirMudança pequena e focada
6 · LimparVocê confirma e ele remove os logs
Quando usar

Condições de corrida, problemas de tempo e de async, lentidão e vazamento de memória, regressões ("isso funcionava antes").

Como ajudar

Descreva o bug com detalhes (mensagens de erro, stack trace, passos), diga o comportamento esperado e o real, e siga os passos de reprodução à risca. Repetir algumas vezes ajuda em bugs intermitentes.

Visual03

Canvases: respostas que viram painel

Um pedido de auditoria virou um painel interativo · reprodução ilustrativa
O que é

Um artefato interativo (seções, números, tabelas) aberto ao lado do chat. Peça um relatório, uma auditoria ou um painel, ou use /canvas.

Reusar

Fica salvo na lista de canvases do projeto e pode ser reexecutado com dados novos. Dá para ajustar pedindo ou editando o código-fonte.

Compartilhar

Publish gera um link para a equipe ver o mesmo painel. Exige plano pago e uma equipe.

Delegação04

Subagentes: dividir para não lotar o contexto

Cada subagente tem a própria janela de contexto e devolve só o resultado. O Cursor já traz três:

SubagenteFaz
ExploreBusca e analisa o código, com um modelo mais rápido e várias buscas em paralelo
BashRoda séries de comandos e filtra a saída longa
BrowserControla o navegador e resume capturas e DOM
Primeiro plano espera o resultado; segundo plano devolve na hora e segue trabalhando sozinho.
# .cursor/agents/revisor-seguranca.md --- name: revisor-seguranca description: Revisa mudanças em busca de falhas de segurança model: inherit readonly: true --- Você revisa código com foco em segurança: entradas não validadas, segredos expostos, injeção de SQL...
Ficam em .cursor/agents/ (projeto) ou ~/.cursor/agents/ (você). Por compatibilidade, o Cursor também lê .claude/agents/. Ou peça: /create-subagent.
Conhecimento05

Skills: pacotes de como fazer

Uma skill é uma pasta com um SKILL.md e, se precisar, scripts, modelos e referências. Segue o padrão aberto Agent Skills, que funciona em outros agentes. O agente carrega a skill quando ela é relevante; você também chama com /nome.

Onde ficaAlcance
.cursor/skills/ · .agents/skills/Projeto
~/.cursor/skills/ · ~/.agents/skills/Seu usuário
.claude/skills/ · .codex/skills/Lidas por compatibilidade

Algumas skills que já vêm no Cursor:

SkillPara quê
/create-rule · /create-skillCriar rules e skills do jeito certo
/create-hook · /create-subagentCriar hooks e subagentes
/canvasMontar um canvas
/automateCriar uma automação
/autopilotCuidar de um PR até ficar pronto
/loopRepetir um pedido em intervalos
/review · /review-securityRevisão de código e de segurança
Custom Mode: escolha a skill no menu / e use Alt + Enter (Mac: Opt + Enter): ela fica ativa a conversa toda, como um checklist de revisão ou um /tdd.

Integração07

MCP: o agente nas suas ferramentas

O Model Context Protocol conecta o agente a sistemas externos: bancos de dados, APIs, Figma, Linear, Notion... Instale pelo Customize (marketplace oficial) ou configure à mão.

TransporteRodaUso típico
stdioLocal, iniciado pelo CursorFerramenta só sua
SSELocal ou remotoServidor compartilhado
Streamable HTTPLocal ou remotoServidor compartilhado, com OAuth
# .cursor/mcp.json (projeto) ou ~/.cursor/mcp.json (global) { "mcpServers": { "meu-servidor": { "command": "npx", "args": ["-y", "mcp-server"], "env": { "API_KEY": "valor" } } } }
Cada conexão MCP e cada chamada de ferramenta pedem aprovação (ou uma lista de permitidas). Instale só servidores de fonte confiável.
Automação local08

Hooks: scripts nos eventos do agente

Hooks rodam scripts seus em momentos do ciclo do agente. Servem para:

  • Formatar o código depois de cada edição
  • Procurar segredos ou dados pessoais
  • Barrar operações arriscadas (ex.: escrita em SQL)
  • Injetar contexto no início da sessão
  • Registrar métricas de uso
# .cursor/hooks.json { "version": 1, "hooks": { "afterFileEdit": [{ "command": "./hooks/format.sh" }] } }
Alguns eventosQuando
sessionStart / sessionEndInício e fim da sessão
beforeSubmitPromptAntes de enviar o pedido
preToolUse / postToolUseAntes e depois de qualquer ferramenta
beforeShellExecutionAntes de um comando no terminal
beforeMCPExecutionAntes de uma ferramenta MCP
beforeReadFile / afterFileEditLeitura e edição de arquivos
subagentStart / subagentStopCiclo dos subagentes
O Cursor também carrega hooks de ferramentas como o Claude Code. Os hooks do projeto rodam até nos agentes da nuvem; os de ~/.cursor, não.
Distribuição09

Plugins e a página Customize

Um plugin empacota rules, skills, agentes, comandos, servidores MCP e hooks num pacote só, fácil de instalar e de compartilhar.

Dois formatos

Agent Plugins (padrão aberto: skills e MCP, com plugin.json) e Cursor Plugins (acrescentam rules, agentes, comandos e hooks, com .cursor-plugin/plugin.json).

Onde achar

No Cursor Marketplace (oficiais), em cursor.directory (comunidade) ou no marketplace interno da sua equipe (Teams).

Onde gerenciar

Na página Customize, na barra lateral: plugins, MCP, rules, skills e subagentes, por usuário, equipe ou projeto.

Plugin é código de terceiros rodando junto com o agente. Antes de instalar, veja quem publica e o que ele inclui, principalmente hooks e servidores MCP.
Revisão10

Agent Review e Bugbot

O Bugbot comenta direto no pull request · reprodução ilustrativa
Agent Review · antes do commit

Revisa as mudanças locais: automático depois de cada commit, com /agent-review ou pela aba Source Control (compara com a main). Profundidade Quick (rápida, barata) ou Deep (lógica complexa, código sensível).

Bugbot · no pull request

Revisa cada atualização do PR e comenta com explicação e sugestão. Para acionar à mão, comente bugbot run ou cursor review. Fix in Cursor e Fix in Web levam direto à correção. Regras do projeto em .cursor/BUGBOT.md.

Nuvem11

Cloud Agents na prática

Agentes em máquinas virtuais isoladas, com um ambiente parecido com o seu: repositório clonado, dependências, segredos, comandos de inicialização e rede.

De onde acionarComo
Agents WindowNovo agente na nuvem ou /in-cloud
CLIComece a mensagem com &
Web e celularcursor.com/agents e app de iOS
Slack · GitHub · LinearMencionando o Cursor
  • Sem repositório: desde agosto de 2026 dá para começar sem GitHub e salvar o trabalho num repositório do Cursor (Cursor Origin).
  • Vai e volta: traga o agente para o seu computador para iterar e devolva para ele seguir sozinho.
  • Máquinas próprias: dá para rodar as ferramentas na sua máquina ou num grupo de máquinas da equipe, com o laço do agente na nuvem.
  • Cobrança: pelo uso de modelos, como o resto.
O código fica na nuvem enquanto o agente trabalha. Confira a política de privacidade do projeto antes.
Nuvem12

Automations: agentes que acordam sozinhos

Uma automação roda um agente na nuvem por agenda ou por evento (GitHub, GitLab, Slack, Linear, webhooks...).

1
Escolha o gatilho: "toda hora", "quando abrirem um PR".
2
Escreva as instruções do agente.
3
Escolha as ferramentas: enviar no Slack, comentar no PR, MCP.
4
Diga se precisa de um, vários ou nenhum repositório.
5
Salve e ative.
/automate Toda segunda às 9h, revise os PRs da semana passada procurando bugs e mande um resumo no canal #engenharia do Slack.
Já prontas no painel

Bugbot, Security Agents (revisão e varredura de vulnerabilidades) e PR Routing & Approval (encaminha PRs e pode aprovar mudanças de baixo risco).

Crie na Agents Window, em cursor.com/automations ou com /automate. Cada execução é um agente na nuvem e é cobrada como tal.
Escala13

Projects: trabalho de semanas

Coordenador

Você conversa com um agente coordenador. Ele não escreve código: planeja, cria e acompanha outros agentes, e traz o resultado para você conferir.

Contexto compartilhado

Arquivos sincronizados entre todas as máquinas do projeto: pesquisas, artefatos e o que os agentes aprendem sobre o código e o seu jeito de trabalhar.

Assinaturas

Peça para ele acompanhar um canal do Slack, seus PRs, o CI ou uma agenda. Ele age sozinho; o selo Listening mostra o que está sendo observado.

Bom para: uma funcionalidade com vários PRs, uma migração, um app inteiro, um trabalho para seguir enquanto você está fora.
Roda na nuvem por padrão (abre um agente local quando precisa testar na sua máquina) e não funciona com o Privacy Mode (Legacy).

Scripts15

O CLI em scripts e CI

# Modo print (-p): sem interação, ideal para scripts agent -p "Adicione comentários JSDoc a este arquivo" # ↑ sem --force, só propõe; não altera arquivos # Com --force (ou --yolo), aplica as mudanças agent -p --force "Refatore para a sintaxe ES6+" # Em lote find src/ -name "*.js" | while read file; do agent -p --force "Adicione JSDoc completo a $file" done
  • CI: há integração com GitHub Actions para rodar o agente nos seus pipelines.
  • Saída estruturada: formatos de saída próprios para outros programas lerem.
  • ACP: agent acp transforma o CLI num servidor para outros editores.
  • Mesmas regras: rules, mcp.json, AGENTS.md e CLAUDE.md valem no CLI.
--force deixa o agente alterar arquivos sem confirmação. Use em branch separado, com Git limpo e revisão antes do merge.
Compatibilidade16

Vindo do Claude Code

O Cursor lê vários arquivos do ecossistema do Claude Code. Dá para usar as duas ferramentas no mesmo projeto sem duplicar tudo.

No Claude CodeNo Cursor
CLAUDE.mdAGENTS.md e .cursor/rules/*.mdc; o CLI do Cursor também lê o CLAUDE.md
.claude/skills/Lidas como estão; o lugar próprio é .cursor/skills/ ou .agents/skills/
.claude/agents/Lidas como subagentes; o lugar próprio é .cursor/agents/
Hooks do Claude CodeCarregados como hooks de terceiros; o formato próprio é .cursor/hooks.json
.mcp.json / servidores MCP.cursor/mcp.json ou ~/.cursor/mcp.json, mesmo protocolo
Plan mode, subagentes, /loopPlan Mode, subagentes e /loop com a mesma ideia
Skills seguem o padrão aberto Agent Skills: a mesma skill pode servir ao Cursor, ao Claude Code e a outros agentes.

Quiz de fixação18

Teste o que ficou

1. O que o Debug Mode faz antes de corrigir?

A) Reescreve o arquivo inteiro
B) Levanta hipóteses, adiciona logs e pede que você reproduza o bug
C) Abre um PR
D) Desliga os testes
B. Evidência em tempo de execução.

2. Como acionar o Bugbot manualmente num PR?

A) Comentando bugbot run ou cursor review
B) Reiniciando o GitHub
C) Só pelo Slack
D) Não é possível
A. E as regras ficam em .cursor/BUGBOT.md.

3. Qual a principal vantagem de um subagente?

A) É sempre mais barato
B) Trabalha com o próprio contexto e devolve só o resultado
C) Não precisa de modelo
D) Só roda na nuvem
B. A conversa principal fica limpa.

4. Onde fica a configuração de servidores MCP do projeto?

A) .cursor/mcp.json
B) package.json
C) .cursorignore
D) AGENTS.md
A. E ~/.cursor/mcp.json para todos os projetos.
Recapitulando

Uma caixa de ferramentas,
um recurso por problema

Além de escrever e delegar, o Cursor depura com evidência (Debug Mode), mostra resultados em painéis (Canvases), divide o trabalho (subagentes), guarda bons fluxos (skills e comandos /), conecta suas ferramentas (MCP, hooks, plugins), revisa (Agent Review e Bugbot) e escala com Cloud Agents, Automations, Projects, integrações e o CLI em scripts. Boa parte é compatível com o que você já usa no Claude Code.
