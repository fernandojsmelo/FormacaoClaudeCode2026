O próprio guia de início do Cursor propõe um caminho curto: da instalação até a primeira mudança útil. Esta aula segue esse roteiro e acrescenta o que você precisa para o dia a dia.

Antes de começar

Uma conta

Crie grátis em cursor.com. O plano Hobby basta para seguir esta aula; os pedidos ao Agent é que são limitados.

Um projeto com Git

De preferência pequeno, ou uma cópia de teste. Assim, qualquer mudança do agente pode ser desfeita.

Uma tarefa pequena

Algo de baixo risco para a primeira mudança: um texto, um ajuste visual, um teste que falta.

Passo 102

Instalar e entrar

Windows 10+

Baixe em cursor.com/download, rode o .exe e siga o assistente. Há versão para o sistema todo e só para o seu usuário (x64 e ARM64).

macOS 12+

Abra o .dmg e arraste o Cursor para Aplicativos. Funciona em Apple Silicon e Intel.

Linux

Prefira o repositório oficial (apt ou dnf): cria o ícone, atualiza sozinho e instala as ferramentas de linha de comando. O AppImage é a opção portátil.

# Debian/Ubuntu: chave, repositório e instalação curl -fsSL https://downloads.cursor.com/keys/anysphere.asc | gpg --dearmor | sudo tee /etc/apt/keyrings/cursor.gpg > /dev/null echo "deb [arch=amd64,arm64 signed-by=/etc/apt/keyrings/cursor.gpg] https://downloads.cursor.com/aptrepo stable main" | sudo tee /etc/apt/sources.list.d/cursor.list > /dev/null sudo apt update && sudo apt install cursor # Fedora/RHEL: crie /etc/yum.repos.d/cursor.repo (baseurl https://downloads.cursor.com/yumrepo) e rode: sudo dnf install cursor
Ao abrir pela primeira vez, entre com a sua conta do Cursor (dá para criar uma grátis em cursor.com). O guia oficial diz que tudo leva menos de cinco minutos.

Passo 205

Peça um mapa do projeto

O primeiro pedido sugerido pela documentação não muda nada: pede ao agente que explique o código. Ele busca no repositório, lê os arquivos relevantes e resume como o projeto se organiza.

# Prompt sugerido pelo Quickstart (pode escrever em português) Explique este projeto. Mostre os principais pontos de entrada, os módulos mais importantes e o que eu preciso ler antes de fazer mudanças.
Quer garantia de que nada vai mudar? Troque para o modo Ask (Shift + Tab): ele é somente leitura.
Use a resposta como guia. Peça para detalhar um módulo, explicar uma função ou desenhar o fluxo de uma requisição. É o jeito mais rápido de se orientar num código desconhecido.
Passo 306

Uma primeira mudança pequena

Com o projeto entendido, peça sugestões e escolha uma. Boas primeiras tarefas têm baixo risco: um texto, um pequeno ajuste de interface.

Sugira três melhorias pequenas e seguras neste projeto. Explique os prós e contras de cada uma e espere eu escolher.
Já sabe o que quer? Peça direto e descreva o resultado esperado, não só a ação.
Escrevendo você mesmo

Comece a digitar e veja o Tab: Tab aceita, Esc recusa, Ctrl + → aceita palavra por palavra.

Ajuste localizado

Selecione o trecho, Ctrl + K, descreva a mudança e Enter. Para só perguntar, Alt + Enter.

Vários arquivos

Selecione e use Ctrl + L: o Agent abre com a seleção como contexto.

Passo 407

Revisar o diff e verificar

1
Acompanhe as edições aparecendo no diff enquanto o agente trabalha.
2
Leia cada mudança: Keep para manter, Undo para desfazer, Review para ver em detalhe.
3
Peça ao agente que rode as verificações que o projeto já tem: testes, checagem de tipos, linter ou build.
4
Gostou? Faça o commit. Não gostou? Restore Checkpoint na mensagem anterior volta os arquivos.
Rode os testes e o linter do projeto. Se algo falhar, explique a causa antes de corrigir.
Checkpoint não é commit. Ele desfaz o que o agente fez e fica só no seu computador. O histórico do projeto continua sendo o Git.
Errou o rumo no meio da tarefa? Mande uma correção com Ctrl + Enter (redireciona na hora) ou use Stop.
Contexto08

Apontar o caminho com @

O agente encontra os arquivos sozinho, mas quando você sabe o que importa, digite @ na caixa de mensagem e anexe.

Você digitaO que entra no contexto
@auth.ts · @src/components/Arquivos e pastas
@TerminalsA saída do terminal
@ChatsUma conversa anterior
@Commit · @BranchMudanças não commitadas ou o diff do branch contra a main
@BrowserO navegador embutido
@nome-da-ruleUma rule aplicada manualmente
  • Imagens: arraste ou cole (Ctrl + V) um print, um layout ou uma mensagem de erro.
  • Voz: clique no microfone e dite o pedido; revise a transcrição antes de enviar.
  • Anel de contexto: ao lado da caixa de mensagem, mostra quanto da janela do modelo já foi usada. Clique para ver por categoria (rules, ferramentas, MCP, conversa...).
  • Janela cheia: o Cursor resume as partes antigas da conversa. Para uma tarefa nova, prefira uma conversa nova.
Passo 509

Plan Mode para o que é maior

Ative

Shift + Tab até o modo Plan. O Cursor também sugere sozinho em pedidos complexos.

Responda

O agente pesquisa o código e faz perguntas para fechar os requisitos.

Edite

O plano sai em Markdown. Ajuste pelo chat ou direto no arquivo; Save to workspace guarda no projeto.

Construa

Clique em Build. Ficou diferente do esperado? Desfaça, refine o plano e rode de novo.

Terminal11

Quanto o agente pode rodar sozinho

O agente roda comandos (instalar dependências, testes, build) conforme o Run Mode, em Cursor Settings → Agents → Approvals & Execution.

Run ModeO que roda sem perguntarPara quem
Auto-review (padrão)Comandos da lista de permitidos; os outros rodam numa sandbox quando possível; o resto passa por um classificador que libera ou bloqueiaA maioria das pessoas
AllowlistSó o que está na sua lista (com sandbox opcional)Quem quer controle fino
Run EverythingTudo, sem aprovaçãoAmbientes descartáveis
# .cursor/permissions.json (no projeto) ou ~/.cursor/permissions.json { "autoRun": { "block_instructions": [ "Todo comando de deploy deve pedir aprovação." ] } }
O classificador do Auto-review não é uma barreira de segurança: pode errar. Dica da documentação: peça ao próprio agente "quero aprovar todo comando X" e ele ajusta o permissions.json.
Navegador12

O agente testa no navegador

Sem instalar nada, o Agent controla um navegador para testar o app, conferir mudanças visuais e investigar erros.

  • Navega, clica, digita e rola a página.
  • Tira capturas de tela e "enxerga" o resultado.
  • Lê o console e o tráfego de rede para achar erros.
  • Detecta o servidor de desenvolvimento já rodando e usa a porta certa.
  • Cookies e login persistem por projeto, isolados entre projetos.
# Exemplo da documentação (acessibilidade) @Browser Verifique o contraste das cores, o HTML semântico e os rótulos ARIA, teste a navegação pelo teclado e aponte imagens sem texto alternativo.
Combine com o fluxo da aula: o agente muda o código, abre a página e confere o resultado antes de você revisar.
Passo 613

Suas primeiras rules

Project rules ficam em .cursor/rules/, em arquivos .mdc (um .md comum ali é ignorado). O cabeçalho define quando a rule entra:

TipoCabeçalho
Always ApplyalwaysApply: true
Por arquivoglobs: src/**/*.tsx
Inteligentedescription: ... (o agente decide)
Manualsem os três: só com @nome
# .cursor/rules/componentes.mdc --- globs: src/components/**/*.tsx alwaysApply: false --- - Use exports nomeados, não default - Mantenha componentes com menos de 200 linhas - Prefira composição a repassar props por várias camadas
Prefere simplicidade? Um AGENTS.md na raiz também vale como rule. E o CLI do Cursor lê até um CLAUDE.md existente.
Privacidade14

O que o agente não deve ler

Crie um .cursorignore na raiz com os padrões a excluir do contexto da IA:

node_modules/ dist/ *.min.js .env*
  • O Cursor já ignora .env, .git/ e arquivos de lock
  • Respeita automaticamente o .gitignore
  • Use o .cursorignore para o que vai além dele
Por que ignorar

Arquivos gerados e grandes, segredos e credenciais, binários e código de terceiros só trazem ruído ou risco.

Limite importante: comandos de terminal e ferramentas MCP rodam fora desse controle e ainda podem ler arquivos ignorados. Segredo de verdade não fica no repositório.
Ligue o Privacy Mode (Settings → General) para que seu código não seja usado em treinamento.
Paralelo15

Mais de um agente ao mesmo tempo

Worktrees

Cada agente trabalha numa cópia isolada do Git, sem conflito com a sua pasta principal. A interface de worktrees fica na Agents Window; no editor, use os comandos de worktree.

Preparar a cópia

O arquivo .cursor/worktrees.json diz o que rodar ao criar cada worktree, como npm ci e copiar o .env.

Mandar para a nuvem

Na Agents Window, /in-cloud passa a tarefa a um agente na nuvem. No CLI, comece a mensagem com &.

# .cursor/worktrees.json (exemplo da documentação para Node.js) { "setup-worktree": [ "npm ci", "cp $ROOT_WORKTREE_PATH/.env .env" ] }
A documentação não recomenda criar links simbólicos para dependências dentro do worktree. Use um gerenciador rápido, como pnpm, bun ou uv.

Boas práticas18

Hábitos que fazem diferença

  • Uma conversa por tarefa; ao mudar de assunto, abra outra
  • Descreva o resultado esperado, não só a ação
  • Use @ quando souber os arquivos; deixe o agente buscar quando não souber
  • Plan Mode para tudo que toca vários arquivos
  • Peça testes, linter e build antes de aceitar
  • Commit pequeno depois de cada mudança aprovada
  • Rules curtas e específicas, versionadas com o código
  • Segredos fora do repositório e do contexto
  • Run Mode em Auto-review; Run Everything só em ambiente descartável
  • Fique de olho no anel de contexto e no consumo do plano
Quando o agente erra feio: em vez de remendar com vários pedidos, desfaça (checkpoint), refine o pedido ou o plano e rode de novo. A documentação diz que isso costuma ser mais rápido e dá um resultado mais limpo.
Quiz de fixação19

Teste o que ficou

1. Em que pasta e extensão ficam as Project Rules?

A) .cursor/rules, arquivos .mdc
B) .cursor/rules, arquivos .txt
C) Na raiz, arquivos .json
D) Só nas configurações
A. Um .md comum ali é ignorado.

2. Qual é o Run Mode padrão?

A) Run Everything
B) Ask Every Time
C) Auto-review
D) Allowlist sem sandbox
C. Lista, sandbox e classificador.

3. Como incluir a saída do terminal no pedido?

A) Copiar e colar sempre
B) @Terminals
C) /terminal
D) Não é possível
B. O @ anexa contexto.

4. O que fazer quando o resultado do Plan Mode não ficou como esperado?

A) Remendar com dez pedidos
B) Apagar o projeto
C) Desfazer, refinar o plano e construir de novo
D) Trocar de editor
C. É o conselho da própria documentação.
Recapitulando

Entender, mudar,
revisar, planejar

Instale, abra o projeto e comece pedindo um mapa do código. Faça uma mudança pequena, revise o diff e peça os testes antes de aceitar. Para o que é maior, use o Plan Mode.
