Aqui está o porquê começar pelo workflow (com pitadas de IA) é a melhor jogada, e como você pode evoluir isso:

1. O "Workflow Inteligente": O Meio Termo Perfeito

Você não precisa abrir mão da IA. Em vez de criar um agente que decide o que fazer, você cria um workflow rígido onde a IA executa tarefas específicas dentro de cada etapa.

  • Etapa 1 (Workflow): O chamado chega.
  • Etapa 2 (IA integrada): Uma chamada de LLM lê o texto, categoriza o problema (ex: "Bug de Login", "Financeiro", "Dúvida Comercial") e analisa o sentimento do cliente (irritado, calmo).
  • Etapa 3 (Workflow): Baseado na categoria que a IA definiu, o workflow direciona o chamado. Se for "Financeiro", joga para o sistema de pagamento. Se for "Bug", abre um card no Jira.
  • Etapa 4 (IA integrada): A IA redige uma resposta padrão personalizada, mas o workflow exige que um humano clique em "Enviar".

2. Por que essa abordagem é melhor para começar?

  • Controle total: Você sabe exatamente o que vai acontecer em cada etapa.
  • Custo menor: Chamadas de IA estruturadas (só para classificar ou resumir) gastam muito menos tokens do que um agente rodando em loop pensando em como resolver o problema.
  • Fácil de auditar: Se algo der errado, você sabe exatamente qual caixinha do fluxo falhou.

Quando vale a pena colocar um "Agente" no suporte?

Deixe os agentes para a ponta final do seu atendimento, quando o problema já foi filtrado.

Por exemplo: após o workflow identificar que o chamado é sobre "Como configurar a API", ele pode passar o controle para um Agente de Suporte Técnico. Esse agente terá acesso à documentação da sua empresa (via RAG) e ferramentas para testar o código do usuário e responder de forma interativa. Se ele não resolver em 3 tentativas, o fluxo puxa o chamado de volta para um humano.

Resumo da ópera: Desenhe o esqueleto com um workflow e use a IA como os músculos para carregar o peso (classificar, resumir, responder). Quando essa estrutura estiver sólida, você começa a dar autonomia (agência) para ela resolver tarefas complexas sozinha.

💸 O Custo Oculto dos Tokens

Um agente não faz apenas uma pergunta e traz uma resposta. Ele opera em um ciclo de Pensamento → Ação → Observação. Para cada microdecisão que ele toma, ele precisa reenviar todo o histórico da conversa e as instruções das ferramentas para o modelo (LLM).

O consumo de tokens escala de forma assustadora:

  • Chamada Direta/Workflow: 1x custo base. Você envia o chamado do Zendesk, a IA categoriza em uma única rodada e acabou.
  • Agente Autônomo Solitário: ~4x mais caro. Ele vai ler, decidir qual ferramenta usar, testar a ferramenta, ler o resultado e formular a resposta.
  • Sistema Multi-Agente: ~15x (ou mais) mais caro. Os agentes começam a "conversar" entre si. O Agente A pede ajuda para o Agente B, que formata um relatório para o Agente C aprovar. Se o prompt não estiver blindado, eles podem entrar em looping e derreter o seu limite do cartão de crédito em minutos.

🔍 Casa Iluminada vs. Floresta sem Mapa

Além do bolso, existe o fator sanidade mental na hora de dar manutenção:

  • Workflow (A Casa Iluminada): No n8n, se o chamado do cliente não foi respondido, você abre o histórico de execuções e vê exatamente onde travou: "Ah, o nó de IA categorization respondeu 'Financeiro', mas escrevi 'financeiro' com 'f' minúsculo na condicional". Você corrige em 10 segundos.
  • Agente (A Floresta sem Mapa): O agente toma um caminho imprevisível. Para descobrir por que ele respondeu algo absurdo para o cliente, você precisa escavar uma montanha de logs de texto (os traces) para entender em qual linha de raciocínio ele se perdeu.

🎯 A Estratégia de Implementação Progressiva

A regra de ouro definitiva para o seu projeto no Zendesk é subir os degraus da complexidade apenas quando o degrau anterior chorar:

1. Nível 1 (O mais simples): Uma chamada única de IA com o contexto certo dentro de um nó fixo do n8n. Resolve 90% dos problemas de triagem, resumo e classificação.

2. Nível 2 (Workflow Inteligente): O que você vai fazer. Várias chamadas de IA simples e isoladas, conectadas por regras rígidas de código (IF/ELSE, Switches).

3. Nível 3 (Agente Pontual): Um agente controlado dentro de um único nó do n8n, com apenas duas ou três ferramentas específicas (ex: "buscar_faturamento_no_banco").

4. Nível 4 (Ecossistema de Agentes): Frameworks complexos. Deixe isso para quando você tiver um orçamento gordo e um problema que nenhuma automação tradicional consiga resolver.

Começando pelo simples (Nível 2), você garante um sistema barato, previsível e fácil de consertar.

Para blindar o seu fluxo contra qualquer "engasgo" da IA e garantir que o n8n continue rodando liso, nós vamos usar duas camadas de segurança: uma expressão/código de tratamento e o nó de roteamento (Switch) [n8n.io].

Aqui está exatamente como configurar essas duas etapas essenciais:

🛡️ Passo 1: A Expressão de Segurança (Tratamento de Erros)

Se por algum motivo a IA responder um texto inválido ou faltar algum campo, nós não podemos deixar o n8n quebrar. Logo após o nó da IA, adicione um nó do tipo Code (configurado para JavaScript) [n8n.io].

Esse código vai interceptar a resposta, tentar ler o JSON e, se algo der errado, ele injeta valores padrão (fallback) para o chamado ir para uma fila de contingência humana.

Cole este código no seu nó Code:

// Captura a saída do nó anterior (IA)
let aiResponse = $json;
// Define os valores padrão de segurança (Fallback)
let resultadoFinal = {
categoria: "nao_classificado",
urgencia: "media",
resumo_curto: "Falha na triagem automática da IA."
};
try {
// Se a IA mandou uma string em vez de um objeto, tenta converter
if (typeof aiResponse === 'string') {
aiResponse = JSON.parse(aiResponse);
} else if (aiResponse.output && typeof aiResponse.output === 'string') {
// Caso o nó do n8n jogue a resposta dentro de um campo 'output'
aiResponse = JSON.parse(aiResponse.output);
}
// Valida se os campos obrigatórios existem na resposta
if (aiResponse.categoria && aiResponse.urgencia) {
resultadoFinal.categoria = aiResponse.categoria.toLowerCase().trim();
resultadoFinal.urgencia = aiResponse.urgencia.toLowerCase().trim();
resultadoFinal.resumo_curto = aiResponse.resumo_curto || "Sem resumo disponível.";
}
} catch (e) {
// Se o JSON for totalmente inválido, o código cai aqui e mantém o fallback com segurança
console.log("Erro ao processar JSON da IA, usando fallback.", e);
}
return resultadoFinal;
Use o código com cuidado.

🔀 Passo 2: O Próximo Nó de Roteamento (O Switch)

Agora que a saída está 100% limpa e garantida pelo código acima, adicione um nó Switch logo em seguida [n8n.io]. O Switch funciona como o guarda de trânsito do seu workflow: ele lê a categoria e joga o chamado para o caminho certo. Configuração do nó Switch no n8n:

1. Data Type: Selecione String [n8n.io].

2. Value 1: Clique na engrenagem e use a expressão para pegar a categoria do nó de código anterior: {{ $json.categoria }} [n8n.io].

3. Routing Rules (Regras de Roteamento): Crie 5 regras usando a operação Equal (Igual a) [n8n.io]:

  • Equal → financeiro (Direciona para a saída 0)
  • Equal → bug_tecnico (Direciona para a saída 1)
  • Equal → comercial (Direciona para a saída 2)
  • Equal → duvida_uso (Direciona para a saída 3)
