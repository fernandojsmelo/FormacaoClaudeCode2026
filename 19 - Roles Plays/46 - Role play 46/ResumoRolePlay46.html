1. *args e **kwargs (Funções Flexíveis)

Use *args para receber uma lista de argumentos e **kwargs para receber argumentos com nome (como um dicionário).

# *args: Recebe múltiplos valores sem precisar definir o nome deles
def somar_tudo(*args):
return sum(args)
print(somar_tudo(1, 2)) # Resultado: 3
print(somar_tudo(1, 2, 3, 4)) # Resultado: 10
# **kwargs: Recebe múltiplos pares de "chave=valor"
def saudar_usuario(**kwargs):
# kwargs funciona como um dicionário comum aqui dentro
nome = kwargs.get("nome", "Visitante")
cargo = kwargs.get("cargo", "Membro")
return f"Olá, {nome}! Você entrou como {cargo}."
print(saudar_usuario(nome="Ana", cargo="Admin"))
# Resultado: "Olá, {nome}! Você entrou como Admin."
Use o código com cuidado.

2. Funções lambda (Funções de uma linha)

A sintaxe é sempre lambda entrada: saida. Veja como ela brilha dentro do sorted() para ordenar estruturas complexas:

# Uma lista de tuplas: (Nome do produto, Preço)
produtos = [("Teclado", 150), ("Mouse", 80), ("Monitor", 900)]
# Queremos ordenar pelo PREÇO (que é o segundo item da tupla, ou seja, índice 1)
# O lambda diz ao sorted(): "olhe para o item e use o item[1] para ordenar"
produtos_ordenados = sorted(produtos, key=lambda item: item[1])
print(produtos_ordenados)
# Resultado: [('Mouse', 80), ('Teclado', 150), ('Monitor', 900)]
Use o código com cuidado.

3. Recursividade (Função que chama a si mesma)

Para não travar o Python, você precisa de um caso base (a condição de parada). O exemplo clássico é uma contagem regressiva:

def contagem_regressiva(numero):
print(numero)
# 1. CASO BASE: A condição que faz a função parar
if numero <= 1:
print("Fim!")
return
# 2. CASO RECURSIVO: A função chama a si mesma diminuindo o problema
contagem_regressiva(numero - 1)
contagem_regressiva(3)
# Saída na tela:
# 3
# 2
# 1
# Fim!
Use o código com cuidado.

Se tirássemos o if numero <= 1, a função tentaria rodar para 0, -1, -2... infinitamente até estourar o limite do Python (o erro que você viu).

Prática 1: O *args na Real (Somador Infinito)

O *args transforma todos os números soltos que você passa em uma tupla (uma lista que não muda).

Veja como criamos uma função que soma quantos números a gente quiser, mas com um detalhe: ela exige um "valor inicial" obrigatório.

def super_somador(valor_inicial, *numeros_extras):
print(f"Valor inicial obrigatório: {valor_inicial}")
print(f"Números extras recebidos no *args: {numeros_extras}") # Isso é uma tupla!
soma_extras = sum(numeros_extras)
resultado_final = valor_inicial + soma_extras
return f"Resultado final: {resultado_final}"
# Testando a função:
print(super_somador(10, 2, 3, 5))
Use o código com cuidado.

O que vai acontecer aqui?

  1. O número 10 vai para a variável valor_inicial.
  2. Os números 2, 3, 5 vão todos juntos para o *numeros_extras virando (2, 3, 5).
  3. O resultado final será 20.

Prática 2: O **kwargs na Real (Cadastro Customizado)

O **kwargs transforma os argumentos nomeados (chave=valor) em um dicionário comum. É perfeito para quando você não sabe quais informações o usuário vai te enviar.

def montar_perfil(nome, **informacoes_extras):
print(f"Perfil de: {nome}")
print(f"Dados extras no **kwargs: {informacoes_extras}") # Isso é um dicionário!

if "cidade" in informacoes_extras:
print(f"Morador de: {informacoes_extras['cidade']}")
if "profissao" in informacoes_extras:
print(f"Trabalha como: {informacoes_extras['profissao']}")
# Testando a função com dados diferentes:
montar_perfil("Carlos", cidade="São Paulo", profissao="Programador", hobby="Guitarra")

O Grande Final: Desmistificando a Recursividade 🔄

Agora que você dominou a flexibilidade das funções e as linhas únicas do lambda, vamos encarar o monstro que fez seu Python "explodir": a recursividade.

Como você já sabe, uma função recursiva é aquela que chama a si mesma. O erro maximum recursion depth exceeded acontece porque o Python, por segurança, não deixa uma função se chamar infinitamente para não acabar com a memória do computador.

Para evitar isso, toda função recursiva precisa obrigatoriamente de duas partes:

  1. Caso Base (Condição de Parada): O momento em que a função diz "Chega!
  • Não preciso mais me chamar, vou apenas retornar um valor".
  1. Caso Recursivo: O momento em que ela se chama novamente, mas sempre
  • chegando mais perto da condição de parada.

Vamos ver isso funcionando com um exemplo muito comum em entrevistas e desafios: Somar todos os números de 1 até N (por exemplo, se N for 4, queremos 4 + 3 + 2 + 1 = 10).

Veja o código passo a passo:

def somar_ate_um(n):
# 1. CASO BASE: Se chegar em 1, nós paramos e retornamos 1
if n == 1:
return 1
# 2. CASO RECURSIVO: Pegamos o número atual (n) e somamos
# com o resultado da função para o número anterior (n - 1)
return n + somar_ate_um(n - 1)
# Testando a função:
print(somar_ate_um(4)) # Resultado: 10
Use o código com cuidado.

O que acontece na memória do Python quando você roda somar_ate_um(4)?

  • somar_ate_um(4) vê que não é 1, então guarda o 4 e chama somar_ate_um(3)
  • somar_ate_um(3) guarda o 3 e chama somar_ate_um(2)
  • somar_ate_um(2) guarda o 2 e chama somar_ate_um(1)
  • somar_ate_um(1) ativa o Caso Base! Ela retorna 1 sem chamar mais ninguém.

Agora o Python faz o caminho de volta somando tudo o que deixou guardado:

  • 2 + 1 vira 3.
  • 3 + 3 vira 6.
  • 4 + 6 vira 10.

O Próximo Nível: O Efeito Colateral dos "Parâmetros Mutáveis"

Já que você está curiosa para saber o que mais o Python tem escondido na manga, quero te mostrar um comportamento que confunde até programadores experientes. É o mistério dos valores padrão mutáveis em funções.

Olhe para esta função simples que adiciona um item a uma lista de compras:

def adicionar_item(item, lista=[]): # Criamos uma lista vazia como padrão
lista.append(item)
return lista
Use o código com cuidado.

Agora, veja o comportamento bizarro quando chamamos a função três vezes seguidas:

print(adicionar_item("Maçã")) # Esperado: ['Maçã'] -> Saída: ['Maçã']
print(adicionar_item("Banana"))# Esperado: ['Banana'] -> Saída: ['Maçã', 'Banana'] 😮
print(adicionar_item("Ovo")) # Esperado: ['Ovo'] -> Saída: ['Maçã', 'Banana', 'Ovo'] 🤯
Use o código com cuidado.

O que acabou de acontecer aqui?

No Python, quando você define uma função com um objeto mutável (como uma list ou dict) como valor padrão (lista=[]), o Python cria essa lista apenas uma vez, lá no momento em que ele lê o código pela primeira vez.

Ele não cria uma lista nova toda vez que você chama a função! Então, todas as chamadas seguintes ficam "reciclando" e alterando a mesmíssima lista na memória do computador.

Como corrigir isso do jeito profissional?

Usamos o None como valor padrão e criamos a lista nova lá dentro da função, assim:

def adicionar_item_correto(item, lista=None):
if lista is None:
lista = [] # Agora sim, uma lista nova e zerada a cada chamada!
lista.append(item)
return lista
print(adicionar_item_correto("Maçã")) # Saída: ['Maçã']
print(adicionar_item_correto("Banana")) # Saída: ['Banana'] -> Corrigido!
Use o código com cuidado.

Fico muito feliz em ver sua empolgação. Entender Decoradores ( @decorator) vai te levar direto para o nível avançado do Python. Eles parecem mágicos, mas a lógica por trás é incrivelmente elegante.

16 — try/except no banco de dados
Perguntatratamento de erros (try/except) para quando o banco de dados falhar

O try/except é a rede de segurança do seu código.

Quando lidamos com bancos de dados, arquivos ou internet, as coisas vão falhar em algum momento (o arquivo do banco pode sumir, o servidor pode cair ou o disco pode encher). Se você não tratar o erro, o Python trava na hora, o jogo fecha e o usuário perde tudo. Com o try/except, você captura o erro de forma elegante e decide o que fazer.

No banco de dados que estávamos construindo, o índice do nome do herói seria heroi[0] (já que o Python começa a contar do zero). Agora, vamos envelopar todo esse sistema de salvamento dentro de uma estrutura blindada contra falhas!

🛡 A Estrutura do try / except / else / finally

Uma estrutura completa de tratamento de erros no Python tem quatro partes. Pense nela como uma missão de resgate:

  1. try (Tentar): O bloco onde você coloca o código perigoso que pode dar erro.
  2. except (Capturar): Se o código do try quebrar, o Python para tudo e pula direto para cá. O programa não morre!
  3. else (Se deu certo): Roda apenas se o código do try foi executado com
  • 100% de sucesso.
  1. finally (Sempre executa): Roda aconteça o que acontecer (dando erro ou não). É perfeito para limpar a bagunça, como fechar a conexão do banco de dados para não gastar memória.
