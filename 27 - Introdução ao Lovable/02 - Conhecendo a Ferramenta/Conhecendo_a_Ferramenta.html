Primeiro acesso01

Criando a conta e o primeiro workspace

Não há nada para instalar nem configurar: o Lovable roda no navegador. Na primeira vez, a conta já vem com um workspace pessoal no plano Free, pronto para construir.

1

Cadastre-se em lovable.dev

Com e-mail, Google, GitHub ou Apple. Empresas podem usar login único (SSO).

2

Ou comece pelo prompt

Dá para digitar o pedido na página inicial antes de se cadastrar. O Lovable pede o cadastro ao enviar e guarda o seu prompt.

3

Chegue ao painel inicial

Depois do login, o Lovable abre o painel, com a caixa de prompt no centro.

4

Proteja a conta

Ative a autenticação em dois fatores (2FA) nas configurações da conta, como vimos no módulo 26.

Conta, workspace e projeto
  • A conta é você: um login para tudo
  • O workspace é onde ficam os projetos, os membros e os créditos. Você pode participar de vários
  • Cada projeto é um app, dentro de um único workspace
No plano Free você tem 5 créditos de build por dia, até 30 por mês. É o bastante para acompanhar as aulas com calma, desde que cada pedido seja claro.
Painel inicial02

O painel inicial (dashboard)

O painel é o ponto de partida: é daqui que você cria projetos, abre conversas e chega às configurações do workspace.

A caixa de prompt

Fica no centro. Com o modo Build selecionado, o que você descreve vira um projeto novo. Com Chat, vira uma conversa. Pode ser uma linha ("um app de tarefas com modo escuro") ou uma especificação de vários parágrafos, e o microfone permite ditar.

O botão +
  • Attach: anexar imagens, arquivos ou uma captura de tela como referência
  • Design: aplicar um design system (planos pagos) ou um modelo de design (Business e Enterprise)
  • Connectors: conectar ferramentas (servidores MCP) como contexto
  • Databases: ligar o Lovable Cloud ou um Supabase
Barra lateral
  • Troca de workspace, com a barra de créditos restantes
  • Dashboard, Chats, Search e Connectors
  • Projects, Starred (favoritos) e Recents
  • Menu do usuário: configurações da conta, tema, suporte e sair
Templates

Prefere começar de algo pronto? Na aba Lovable templates você abre um app de exemplo e faz um remix: uma cópia independente, só sua, disponível em qualquer plano.

A visibilidade padrão de um projeto novo é o workspace. Você muda isso depois, no botão Share.

Chat04

O chat do projeto e os três modos

A cada mensagem, o agente do Lovable trabalha em ciclo: reúne contexto do projeto, age com suas ferramentas e confere o resultado antes de seguir. Você escolhe como ele responde com o seletor de modo.

Build (padrão)

Faz a mudança

Altera o projeto diretamente. É a escolha certa para a maioria dos pedidos, de ajustes pequenos a funcionalidades inteiras.

Plan

Planeja antes

Investiga o projeto e escreve um plano para você revisar, editar e aprovar. Não mexe no código até a aprovação. Ideal para mudanças grandes ou arriscadas.

Chat

Só conversa

Discute o app aberto sem alterar nada: como funciona, o que um termo significa, qual abordagem escolher.

Em volta da caixa de texto
  • Microfone: dite o pedido (Alt+V, ou ⌥+V no Mac). O Lovable transcreve e limpa o texto
  • Seletor de modo: Alt+P alterna entre Build, Chat e Plan
  • Botão +: anexar arquivos, adicionar skills e conectores e abrir ferramentas do projeto
Pode perguntar qualquer coisa, não só pedir mudanças: "como esse filtro funciona?". E pode pedir ações: "publique meu app" ou "encontre um domínio para a minha padaria".
Com o Lovable ainda trabalhando, você pode mandar mensagens para corrigir o rumo, responder às perguntas que ele fizer e desfazer mudanças.
Pré-visualização05

Editando apontando na tela

A pré-visualização à direita é o seu app de verdade, rodando ao vivo: dá para clicar em tudo como um usuário faria. A barra de pré-visualização (que substituiu o antigo "Visual edits") permite pedir mudanças apontando, em vez de descrevendo.

Modo da barraPara quê
Select elements SApontar um ou mais elementos e pedir a mudança em linguagem natural. Com Ctrl/Cmd+clique você seleciona vários
Edit text inlineCorrigir um erro de digitação ou trocar um texto direto na página, sem prompt
Draw annotationDesenhar sobre a tela para mostrar uma mudança de layout difícil de descrever
Add a commentDeixar um comentário para você ou para um colega
Teste em vários tamanhos

O botão de dispositivo acima da pré-visualização alterna entre celular, tablet e desktop. Sempre confira a versão de celular: é nela que a maioria das pessoas vai abrir o link.

Quando usar cada coisa: para ajustes visuais pequenos, apontar é mais rápido que descrever. Para funcionalidades e lógica, use o chat.
Lembra das aulas do Codex? É o mesmo princípio do navegador embutido do app desktop: ver o resultado e ajustar em ciclos curtos.
Segurança06

Histórico de versões: sua rede de proteção

Toda mudança que o Lovable faz cria uma versão automaticamente. Não existe botão de salvar: o histórico está sempre completo, e dá para voltar a qualquer ponto.

Pré-visualizar

Abra o History na barra superior e veja como o app estava em qualquer versão anterior.

Reverter

Uma mudança quebrou algo? Volte para a última versão boa. Nada se perde: as mudanças posteriores continuam no chat e podem ser reaplicadas.

Marcar (bookmark)

Marque as versões estáveis, como "antes do login" ou "versão aprovada". Elas ficam na aba Bookmarks.

Rascunhos (drafts)

Pelo nome do projeto você cria um rascunho: uma área separada, com chat próprio, para testar uma ideia sem mexer na versão principal. Se gostar, aceite o rascunho no projeto.

Paralelo com o que já vimos: o histórico faz o papel dos commits do Git, e os rascunhos o das worktrees e branches. É o mesmo raciocínio de experimentar sem medo, agora sem linha de comando.
Na prática07

O primeiro tour em 10 minutos

O guia oficial propõe um primeiro app simples. Adaptado para o português, o exercício passa por todas as áreas que vimos:

Prompt inicial (modo Build): Crie um site para a Café Samambaia, uma cafeteria de bairro. Inclua uma seção principal acolhedora com título e foto, um cardápio interativo em que o visitante filtra os itens por categoria (cafés, café da manhã, almoço, doces), uma seção de horários e uma seção de localização com o endereço e uma breve descrição de "como chegar". Use conteúdo de exemplo realista. Visual aconchegante. Funcione bem no celular. Sem login nem banco de dados por enquanto.
A última linha importa: sem login e sem banco, a primeira versão tem menos coisa para dar errado. As duas coisas entram depois, com um prompt cada.
1

Acompanhe a construção

A primeira versão leva alguns minutos. Depois, clique em tudo na pré-visualização.

2

Peça uma mudança por vez

"Adicione uma seção de especiais do dia entre o cardápio e os horários."

3

Ajuste apontando

Troque um título com Edit text inline, sem gastar prompt.

4

Teste no celular

Troque o dispositivo e confira os filtros.

5

Olhe o histórico

Veja as versões criadas e marque a que ficou boa.

Boas práticas09

Hábitos para começar bem

1

Descreva o resultado, não o código

"Adicione um formulário de cadastro com e-mail e senha" funciona melhor que instruções técnicas.

2

Um pedido por vez

Confira a pré-visualização a cada mudança. Pedidos grandes demais são difíceis de revisar.

3

Use o Plan mode para o que é grande

Aprovar um plano custa menos que desfazer um app inteiro.

4

Seja específico nos erros

"Clicar no filtro de doces não mostra nenhum item. Deveria mostrar os doces." Diga o que, onde e o que era esperado.

5

Marque as versões boas

Um bookmark antes de cada mudança grande é a sua garantia.

6

Economize créditos

Textos e ajustes visuais simples, faça apontando na tela.

Tudo o que você digita ou anexa vai para a plataforma. Use dados fictícios nos exercícios, como vimos no módulo 26 sobre segurança.
Fixação10

Teste rápido

1. Você quer discutir como o app funciona sem que o Lovable mude nada. Qual modo usar?

A) Build
B) Plan
C) Chat
D) Publish
C. O Chat mode conversa sobre o app aberto sem alterar o código.

2. Qual é o jeito mais rápido de corrigir um erro de digitação num título?

A) Escrever um prompt
B) Edit text inline, direto na tela
C) Abrir o Plan mode
D) Reverter a versão
B. O Edit text inline muda o texto direto na pré-visualização, sem precisar de prompt.

3. Uma mudança quebrou o app. O que fazer?

A) Apagar o projeto
B) Abrir o History e reverter para a última versão boa
C) Criar outra conta
D) Nada, não dá para desfazer
B. Cada mudança vira uma versão automaticamente, e reverter não perde as mudanças posteriores, que continuam no chat.

4. Onde ficam o banco de dados e os usuários do app?

A) Na aba Files
B) More → Cloud
C) No botão Share
D) No histórico
B. O menu More → Cloud reúne banco, usuários, armazenamento, jobs, funções, segredos e logs.
