Conceito01

O que é o Lovable

O Lovable é uma plataforma de desenvolvimento full-stack com IA: você descreve em linguagem natural o que quer construir, e ele gera uma aplicação web funcionando, com frontend, backend, banco de dados, autenticação e integrações, tudo apoiado em código editável.

Account

Sua conta

Sua identidade no Lovable. Um único login vale para todos os workspaces de que você participa.

Workspace

O espaço do time

Reúne projetos, membros, cobrança e um saldo compartilhado de créditos.

Project

Um app

Cada projeto é uma aplicação, com chat, pré-visualização, código e histórico de versões.

Chats

Conversas livres

Para pensar ideias fora de um projeto. Quando algo precisa ser construído, o chat manda o trabalho para um projeto.

A diferença para um gerador de protótipos: o resultado é código de verdade, que pode ser sincronizado com GitHub, GitLab ou Bitbucket e entrar no fluxo de engenharia normal da empresa.
O Lovable cobre o ciclo inteiro do produto: da exploração e do protótipo até a publicação e a operação do app no ar.

Público04

Para quem é o Lovable

Não é uma ferramenta só para quem não programa. A documentação descreve quatro grupos de usuários, com necessidades bem diferentes:

  • Produto e design transformando protótipos em ferramentas internas

  • Marketing criando landing pages, sites de campanha e dashboards

  • Times de engenharia revisando e mantendo o código gerado via Git
  • Agências entregando projetos a clientes, com código portável
Grandes empresas
  • Ferramentas internas e aplicações críticas para o negócio
  • Apps com exigências de segurança, conformidade e governança
  • Desenvolvimento com IA integrado aos fluxos de engenharia existentes
Criadores individuais
  • Fundadores lançando produtos e buscando os primeiros clientes
  • Makers com projetos paralelos e pequenos produtos
  • Estudantes e professores em trabalhos e experimentos

Por dentro06

Como o Lovable funciona

CamadaO que o Lovable usa
FrontendApps criados desde 13/05/2026: TanStack Start com renderização no servidor (SSR). Os anteriores usam React + Vite
EstiloTailwind CSS
BackendLovable Cloud, baseado no Supabase: banco, autenticação, armazenamento, tempo real, edge functions e IA. Também é possível conectar um Supabase próprio
HospedagemGerenciada pelo Lovable, com HTTPS, escala automática e domínio próprio
CódigoSincronizável com GitHub, GitLab ou Bitbucket
Três modos de trabalho no projeto
  • Plan mode: investiga o projeto e escreve um plano para você revisar e aprovar antes de qualquer código. O plano fica salvo em .lovable/plan.md
  • Build mode: constrói as mudanças aprovadas
  • Chat mode: conversa sobre o app aberto sem alterar o código, para decidir o que mudar
Familiar? O Plan mode do Lovable segue a mesma ideia do /plan do Codex e do modo de planejamento do Claude Code: planejar antes de construir.
Posicionamento07

Lovable e Claude Code: complementares

No módulo 04 comparamos as duas ferramentas. A conclusão continua valendo: não é uma disputa. Cada uma brilha num ponto diferente do ciclo de desenvolvimento.

LovableClaude Code
Ponto de partidaUma ideia, sem códigoUm repositório existente
InterfaceChat e pré-visualização no navegadorTerminal, IDE e app desktop
InfraestruturaBackend e hospedagem incluídosUsa a infraestrutura que você já tem
StackPadronizada (TanStack/React, Tailwind, Cloud)Qualquer uma
Melhor paraValidar, prototipar e lançar rápidoEvoluir sistemas complexos com controle total
Um fluxo que combina as duas
  1. Validar a ideia e publicar o MVP no Lovable
  2. Sincronizar o código com o GitHub (Git sync)
  3. Clonar o repositório e evoluir partes complexas com o Claude Code
  4. Continuar iterando nos dois, com o Git como fonte da verdade
Atualização em relação ao módulo 04: lá o Lovable aparece com React + Supabase. Hoje os apps novos usam TanStack Start, e o backend padrão é o Lovable Cloud (que usa o Supabase por baixo).
Custos08

Como o Lovable cobra: créditos

Os planos são cobrados por créditos, não por projeto nem por usuário. Um único saldo paga quatro coisas: construir, conversar, manter o app no ar (hospedagem e Cloud) e os recursos de IA usados dentro do app publicado.

Limites09

Onde o Lovable não é a melhor escolha

Saber os limites evita frustração e ajuda a escolher a ferramenta certa para cada caso.

Foco em web

O Lovable constrói aplicações web, que podem ser totalmente adaptadas ao celular. Apps nativos para as lojas não são o alvo da plataforma.

Stack padronizada

Se o projeto exige outra linguagem, framework ou arquitetura específica, uma ferramenta como o Claude Code dá mais controle.

Lógica muito específica

Regras de negócio incomuns e casos de borda podem pedir vários ciclos de prompt ou edição direta do código.

Consumo de créditos

Pedidos vagos geram idas e vindas e gastam créditos. Planejar e descrever bem economiza dinheiro.

Segurança é sua também

O Lovable faz varreduras de segurança, mas revisar as permissões do banco e os segredos continua sendo responsabilidade de quem publica.

Dados sensíveis

Tudo o que você cola no chat vai para a plataforma. Aplique as práticas do módulo 26: anonimize e use conta corporativa.

Antídoto contra a dependência da plataforma: ative o Git sync desde o início. Com o código no seu repositório, você pode continuar o projeto em qualquer ferramenta.

Fixação11

Teste rápido

1. O que o Lovable gera a partir de uma descrição em linguagem natural?

A) Só o layout visual
B) Um app com frontend, backend, banco e autenticação
C) Um app nativo para as lojas
D) Apenas documentação
B. Uma aplicação web full-stack apoiada em código editável.

2. Como os planos do Lovable são cobrados?

A) Por usuário
B) Por projeto
C) Por créditos, num saldo compartilhado
D) Por hora de uso
C. Por créditos, e não por assento nem por projeto. O mesmo saldo paga build, chat, hospedagem e Cloud, e IA no app publicado.

3. Qual modo propõe um plano para você aprovar antes de mexer no código?

A) Build mode
B) Plan mode
C) Chat mode
D) Git sync
B. O Plan mode investiga o projeto e escreve o plano, e o Build mode só age depois da aprovação.

4. Qual é a melhor forma de evitar ficar preso à plataforma?

A) Não usar o Lovable
B) Ativar o Git sync desde o início
C) Usar só o plano Free
D) Nunca publicar
B. Com o código sincronizado no seu repositório, o projeto pode seguir em qualquer ferramenta, como o Claude Code.

O Lovable transforma descrições em linguagem natural em aplicações web full-stack, com backend embutido (Lovable Cloud), hospedagem incluída e código sincronizável com o Git. Ele atende de times de negócio a desenvolvedores, cobra por créditos e complementa o Claude Code em vez de substituí-lo. Conhecer os limites ajuda a usá-lo onde ele brilha.
