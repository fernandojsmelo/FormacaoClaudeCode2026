Introdução ao
JupyterLab

Os exercícios do módulo são notebooks (.ipynb): documentos que misturam texto, código e o resultado de cada execução. O JupyterLab é a interface em que você os abre e roda, célula por célula. Nesta aula: abrir o JupyterLab, conhecer a tela, células de código e de texto, os dois modos e os atalhos, a ordem de execução e o kernel.

O que é01

Um notebook é uma lista de células

Célula de código

Python que você roda; o resultado aparece logo abaixo dela.

Célula Markdown

Texto formatado: títulos, listas, negrito. Explica o que o código faz.

Saída

O que a célula imprimiu. Fica gravada no arquivo ao salvar.

Ideal para engenharia de prompt: muda o prompt de uma célula, roda só ela e compara com a resposta de antes, sem rodar o resto.
Por isso os notebooks do módulo chegam com respostas já gravadas: é o que o modelo devolveu quando foram executados.
Abrindo02

Do terminal ao navegador

Na pasta Eng_prompt, com o venv ativado (aula 02)
jupyter lab
  • O JupyterLab abre sozinho no navegador
  • O endereço fica no terminal, algo como http://localhost:8888/lab?token=…; se o navegador não abrir, copie e cole
  • O terminal precisa ficar aberto: é ele que está rodando o servidor
Abra sempre a partir da pasta do projeto. A documentação recomenda não iniciar o JupyterLab na raiz do disco (C:\ ou /), para não mexer em arquivos do sistema por engano.
Para encerrar: salve os notebooks, volte ao terminal e pressione Ctrl + C (confirme se ele perguntar). Também dá pelo menu File › Shut Down.

Modo de edição

O cursor está dentro da célula: as teclas viram texto. Entra com Enter ou clicando no código.

Modo de comando

A célula está selecionada, sem cursor: as teclas viram comandos (A, B, D D, M, Y). Entra com Esc.

Digitou "a" e apareceu uma célula nova? Você estava no modo de comando.

No macOS, troque Ctrl por Cmd nos atalhos de salvar.

Ordem06

A ordem em que você roda é a que vale

[ ]nunca rodou
[*]rodando agora
[3]foi a 3ª execução
  • Variáveis criadas numa célula ficam na memória para as próximas
  • O número entre colchetes mostra a ordem real das execuções, não a posição na tela
  • Enquanto aparece [*], espere: a chamada à API ainda não voltou
Rodou a célula do prompt antes da primeira · saída real
NameError: name 'client' is not defined
Ao abrir um notebook, rode primeiro a célula 1 (a do load_dotenv() e do client). Depois, as outras em qualquer ordem.
Kernel07

O kernel: o Python por trás do notebook

  • O kernel é o processo Python que executa as células e guarda as variáveis
  • Instalado dentro do venv, o JupyterLab usa o Python do venv: por isso o import groq funciona
  • Cada notebook aberto tem o seu kernel
Menu KernelQuando usar
Interrupt Kernel (■)Uma célula travou ou está demorando demais
Restart Kernel (↻)Começar do zero: apaga todas as variáveis
Restart Kernel and Run All CellsConferir se o notebook roda inteiro, de cima para baixo
Mudou o .env? Reinicie o kernel e rode a célula 1 de novo: a chave antiga continua na memória até lá.
Run All chama a API uma vez por célula. Num notebook com 7 chamadas, são 7 requisições e milhares de tokens da sua cota (aula 01).
Arquivos08

O que fica salvo

  • O .ipynb guarda o código, o texto e as saídas da última execução
  • Edit › Clear Outputs of All Cells (ou Kernel › Restart Kernel and Clear Outputs of All Cells) limpa as respostas antes de compartilhar
  • O JupyterLab cria a pasta .ipynb_checkpoints/ com cópias de segurança; ela já está no .gitignore da aula 02
As saídas podem conter dados sensíveis. Se você imprimir a chave por engano (print(os.environ["GROQ_API"])), ela fica gravada no arquivo: limpe a saída antes de salvar e compartilhar.
Neste curso, ao lado de cada notebook há um .md e um .pdf com o mesmo conteúdo, para ler sem abrir o JupyterLab.
