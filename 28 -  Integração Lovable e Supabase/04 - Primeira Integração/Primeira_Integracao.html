Verificação04

Deu certo? Confira em dois lugares

No Lovable · More → Cloud
  • Nome do projeto Supabase: minha-estante
  • Status do projeto: saudável
  • Atalhos para o painel do Supabase: visão geral, usuários, SQL editor, edge functions e segredos
  • Nenhum aviso de projeto compartilhado
No Supabase
  • O projeto continua ativo (não pausado)
  • Table Editor ainda vazio: a estrutura vem na etapa 3
  • Nenhuma chave foi copiada para o Lovable
O link de conexão mostra Wait for Lovable to finish working? O Lovable ainda está processando um pedido nesse projeto. Espere terminar e tente de novo.
A partir daqui, dados, usuários e arquivos são administrados no painel do Supabase. As telas Database, Users e Storage do Cloud não se aplicam.
Etapa 305

O primeiro pedido ao banco

Uma mudança pequena para ver o ciclo completo: pedido → migration → aprovação → execução → conferência. A tabela generos será usada pelos livros na aula 05.

Prompt (Plan mode): Crie a página inicial do Minha Estante, um app para catalogar livros, só com o título e uma seção "Gêneros". No Supabase, crie a tabela "generos" com id e nome (texto único, obrigatório). Ative RLS: qualquer pessoa pode LER; ninguém cria, altera ou apaga pelo app. Depois, insira: Romance, Conto, Poesia, Biografia, Fantasia e Não ficção. Mostre os gêneros na seção, lidos do banco.
Por que Plan mode

É a primeira mudança no banco: vale ler o plano antes. Confira se ele fala em migration, RLS e política só de leitura.

Por que leitura pública

Gêneros não são dados pessoais e aparecerão até para visitantes sem login. Já a criação e a edição ficam fechadas: ninguém muda a lista pelo app.

Nada de dados pessoais nesta tabela. Os dados de leitores chegam só na aula 06, com login.
Aprovação06

Lendo a migration antes de aprovar

Pedido de aprovação no chat · reprodução ilustrativa

Você não precisa saber SQL para revisar. Procure três coisas:

  • create table public.generos: é a tabela que você pediu
  • enable row level security: o RLS está ligado
  • for select using (true): a única política é de leitura; não há política para insert, update ou delete
Faltou o RLS ou apareceu uma política de escrita aberta? Clique em Reject e peça o ajuste. Aprovar é executar no seu banco de verdade.
A inserção dos seis gêneros é outro pedido de aprovação: o Lovable pede autorização antes de inserir ou alterar dados.

Armadilhas10

Erros comuns na primeira integração

Clicar em Enable Cloud "para testar". O projeto passa a ter backend e o link para conectar o Supabase some. Não há volta automática.
Aprovar sem ler. Uma migration sem RLS, ou com escrita aberta, vai direto para o seu banco.
Conectar o projeto marcado com ⚠. Dois apps no mesmo Supabase sobrescrevem os segredos um do outro.
Autorizar todas as organizações. Vincule só a do curso: todo o workspace passa a enxergá-la.
Criar colunas pelo Table Editor. O código espera a estrutura das migrations. Mudança de estrutura passa pelo Lovable.
Achar que o Lovable "sumiu" com os dados. Com Supabase próprio, os dados ficam no painel do Supabase, não no Cloud.
