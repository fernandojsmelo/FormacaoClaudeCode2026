Conceito01

Backend como serviço

Todo app tem duas metades: a tela que o usuário vê (frontend) e a cozinha que guarda dados, confere quem está logado e processa pedidos (backend). Montar essa cozinha do zero exige servidor, banco, segurança e manutenção. O Supabase entrega essa cozinha pronta, na nuvem.

Frontend
App feito no Lovable

Telas, botões, formulários. Roda no navegador do usuário.

⇄
Backend · Supabase
Banco, login, arquivos e funções

Guarda os dados, confere permissões e executa a lógica que não pode ficar no navegador.

Código aberto

O Supabase é open source e pode até ser instalado em servidor próprio. Aqui, usamos a versão hospedada em supabase.com.

Postgres no centro

O coração é um banco PostgreSQL dedicado, um dos bancos relacionais mais usados do mercado.

Conhecimento que vale fora

Tabelas, SQL e regras de acesso que você aprender aqui servem em qualquer projeto com Postgres.

Segurança04

RLS e as duas chaves

O app no navegador conversa direto com o banco, usando uma chave pública. Parece perigoso, e seria, sem Row Level Security (RLS): regras no próprio banco que decidem, linha a linha, quem pode ler, criar, alterar ou apagar.

ChaveOnde pode ficarPoder
Pública
anon / publishable		No app, no navegadorSó o que as regras de RLS permitem
Secreta
service_role / secret		Só no servidor (Edge Functions, secrets)Ignora o RLS: acesso total
Regra típica do Minha Estante (em português): Um leitor logado pode ler, criar, alterar e apagar apenas os livros em que user_id é igual ao próprio id. Qualquer visitante pode ler os livros com publicado = true.
Tabela sem RLS com a chave pública no app = qualquer pessoa lê e altera tudo. E a chave secreta nunca vai para o código do app nem para o chat.
Comparação05

Lovable Cloud × Supabase próprio

Os dois usam a mesma base do Supabase. A diferença é de quem é o backend e onde você o administra.

Lovable Cloud (módulo 27)Supabase próprio (este módulo)
ConfiguraçãoAutomática, sem outra contaConta e projeto no Supabase
Cobrança do backendCréditos do workspace do LovablePlano do Supabase (tem Free)
Onde administrarTelas do Cloud dentro do LovablePainel do Supabase (Table Editor, SQL Editor…)
Backups e pausaGerenciados pelo LovableVocê gerencia no Supabase
Vários projetos, um bancoNão: cada projeto tem o seuSim: vários projetos podem usar o mesmo Supabase
Projeto que já existe—Conecta um Supabase que você já usa
Não há migração automática entre Cloud e Supabase próprio, em nenhuma direção. Decida no começo; trocar depois é recriar tabelas e mover os dados à mão.
Motivos06

Por que o Supabase próprio neste módulo?

Você é dono do backend

Conta, cobrança e dados ficam no seu Supabase. Se um dia sair do Lovable, o banco continua com você.

Você enxerga tudo

No painel do Supabase você vê cada tabela, regra de RLS, usuário e arquivo, e pode rodar SQL. É ótimo para aprender o que acontece por baixo.

Um banco para vários apps

Lembra do site e do painel da Café Samambaia, que precisaram de uma ponte porque cada um tinha seu Cloud? Com um Supabase próprio, os dois poderiam ler o mesmo banco.

O que muda para você
  • Duas contas e, eventualmente, duas contas a pagar: Lovable (construir) e Supabase (rodar)
  • As telas Database, Users, Storage e Secrets do Cloud não se aplicam: você usa o painel do Supabase
  • Backups e capacidade do servidor são responsabilidade sua
  • Alguns recursos do Lovable exigem o Cloud, como os e-mails personalizados
Para a maioria dos projetos simples, o Cloud basta. O Supabase próprio vale quando você quer controle, visibilidade ou compartilhar o banco.
Na prática07

Como o Lovable trabalha com o seu Supabase

1
Você descreve em português: "guarde os livros com título, autor e nota".
2
O Lovable escreve o SQL da mudança (a migration) e mostra para você aprovar no chat.
3
Aprovado, ele executa no seu Supabase e salva o arquivo em supabase/migrations/, junto com os tipos que o app usa.
4
Você confere o resultado no Table Editor.
Outras coisas que ele faz por você
  • Pede aprovação antes de inserir ou alterar dados
  • Cria buckets de arquivos, também com aprovação
  • Publica Edge Functions e pede as chaves secretas por um campo seguro; elas ficam no Supabase, nunca no código
  • Liga o tempo real quando você pede
Antigamente era preciso colar SQL à mão no SQL Editor. Hoje o Lovable roda as migrations por você, sempre com a sua aprovação.

Armadilhas10

Erros comuns de quem começa

Tabela sem RLS. Com a chave pública no app, os dados ficam abertos para qualquer um. Confira o selo RLS em cada tabela.
Chave secreta no código ou no chat. A service_role ignora todas as regras. Ela só existe no servidor, como segredo.
Esquecer a pausa do Free. Uma semana sem uso e o projeto pausa. Reative antes de mostrar o app para alguém.
Trocar de backend no meio. Não há migração automática entre Cloud e Supabase. Escolha antes de começar.
Editar tabelas pelo painel sem avisar o Lovable. O código do app espera a estrutura das migrations. Mudanças de estrutura devem passar pelo Lovable.
Usar dados reais nos testes. Como na Café Samambaia, teste com dados fictícios.
Quiz de fixação11

Teste o que ficou

1. Qual banco de dados está no centro do Supabase?

A) MongoDB
B) PostgreSQL
C) Planilhas
D) Firebase
B. Um Postgres dedicado, com APIs geradas a partir das tabelas.

2. O que o RLS faz?

A) Acelera consultas
B) Decide, linha a linha, quem pode ler e alterar
C) Faz backup
D) Cria telas
B. Por isso a chave pública pode ficar no app: o banco aplica as regras.

3. Algo que o Supabase próprio permite e o Lovable Cloud não:

A) Ter login
B) Vários projetos do Lovable usarem o mesmo banco
C) Ter tabelas
D) Publicar o app
B. Cada projeto no Cloud tem o seu banco; um Supabase próprio pode ser compartilhado.

4. Onde fica a chave secreta (service_role)?

A) No código do app
B) No Knowledge
C) Só no servidor, como segredo
D) No chat, para o Lovable usar
C. Ela ignora o RLS; exposta, entrega o banco inteiro.
Recapitulando

A cozinha
do seu app

O Supabase é um backend pronto e de código aberto, com Postgres no centro e Auth, Storage, Edge Functions e Realtime em volta. O RLS protege os dados linha a linha, a chave pública vai no app e a secreta só no servidor. Comparado ao Lovable Cloud, o Supabase próprio dá posse, visibilidade e banco compartilhável, em troca de administrar conta, cobrança e backups. O plano Free basta para o Minha Estante.
