Conceito01

O Codex dentro do app desktop

O Codex não tem um app separado: ele é um dos três modos do aplicativo desktop do ChatGPT. Diferente do Codex Cloud (aula 1), aqui o agente trabalha no seu computador, com os arquivos, ferramentas e dependências que já estão instalados nele.

Chat

Conversa

O ChatGPT tradicional, para perguntas e textos. Atalho Ctrl+1 no macOS, ou Alt+1 no Windows e no Linux.

Work

Tarefas longas

Trabalho com arquivos, documentos, planilhas e ferramentas conectadas. Atalho Ctrl+2 ou Alt+2.

Codex

Agente de código

Lê, edita e testa o seu projeto, com terminal, Git e revisão de diff. Atalho Ctrl+3 ou Alt+3.

Por que usar o app em vez da interface web

  • Todos os chats à vista: vários projetos e tarefas longas em paralelo, sem perder contexto.
  • Ambiente real: o agente usa o seu Node, Python, banco local e segredos do projeto, sem precisar configurar um container.
  • Ferramentas integradas: terminal, controles de Git, painel de revisão, navegador embutido e visualização de arquivos.
  • Um lugar só: no mesmo app você escolhe se a tarefa roda localmente, numa worktree ou na nuvem.
Instalação02

Instalando o app em cada sistema

Baixe em chatgpt.com/download, faça login com a conta do ChatGPT, escolha onde trabalhar e selecione Codex → New chat.

macOS

Download direto

Instale pelo site. O sandbox usa o Seatbelt, nativo do macOS, e funciona sem configuração extra.

Windows

Microsoft Store / winget

Roda nativo com PowerShell e o sandbox do Windows, ou dentro do WSL2 com o sandbox do Linux.

winget install --id 9PLM9XGG6VKS -s msstore
Linux preview

.deb / .rpm / script

Ubuntu 24.04 e 26.04, Debian 13, Fedora 43 e 44 e Arch, em x64 e ARM64 (uname -m mostra a sua arquitetura).

Ubuntu / Debian (x64)
cd ~/Downloads
sudo apt install ./chatgpt_amd64.deb
chatgpt            # ou abra pelo menu de aplicativos

# pré-requisito do sandbox no Linux / WSL2
sudo apt install bubblewrap
Ubuntu 24.04: mesmo com o bubblewrap instalado, o Codex pode avisar que não consegue criar o user namespace. A solução documentada é carregar o perfil AppArmor bwrap-userns-restrict (pacote apparmor-profiles) com sudo apparmor_parser -r.
No Fedora, a instalação é sudo dnf install com o .rpm baixado. Para ARM64, troque amd64 por arm64 no nome do pacote.
Onde roda03

Local, Worktree ou Cloud

Ao iniciar um chat no Codex, escolha abaixo da caixa de mensagem onde a tarefa vai rodar. Essa é a decisão mais importante da interface.

ModoOnde executaQuando usarAtenção
LocalDireto na pasta atual do projeto, no seu computadorTarefas rápidas que você quer acompanhar e testar na horaMexe nos mesmos arquivos que você está editando
WorktreeNuma cópia isolada do repositório (Git worktree), também localVárias tarefas em paralelo sem atrapalhar o seu trabalho atualSó funciona em repositórios Git
CloudNum environment na nuvem (o mesmo da aula 1)Tarefas longas que podem rodar com o computador desligadoPrecisa de environment configurado no Codex Cloud
Local e Worktree rodam no seu computador. O repositório, os comandos e as dependências continuam na sua máquina, e nada é enviado para um container.
Regra prática: use Local quando quiser acompanhar a tarefa, Worktree quando quiser várias em paralelo e Cloud quando puder deixar rodando sem a sua máquina.
Segurança04

Sandbox e modos de permissão

Dois controles trabalham juntos. O sandbox define quais arquivos e recursos de rede o agente pode acessar. As aprovações decidem quando ele para e pede autorização para ir além desse limite. O controle de permissões fica abaixo da caixa de mensagem.

padrão

Ask for approval

Trabalha livremente dentro do projeto e pede aprovação para ultrapassar o limite. Aprove com Enter ou recuse com Esc.

opcional

Approve for me

Chamado de Auto-review nas configurações. Mantém o mesmo sandbox, mas os pedidos vão para um agente revisor automático em vez de você.

cuidado

Full access

Remove as restrições do sandbox. O agente não fica limitado à pasta do projeto e pode executar ações destrutivas não intencionais.

No primeiro uso, só Ask for approval aparece no menu. Para liberar os outros modos, vá em Settings → General → Permissions. Isso só deixa o modo disponível; ele não é selecionado sozinho.
O sandbox vale também para os comandos que o agente dispara (git, gerenciadores de pacotes, testes), não só para as edições de arquivo. Em empresas, o administrador pode desabilitar alguns modos.
Paralelismo05

Worktrees e Handoff

Uma worktree é uma segunda cópia (checkout) do repositório. Cada uma tem os seus arquivos, mas todas compartilham o mesmo .git (commits e branches). Assim, várias tarefas rodam em paralelo sem interferir no seu checkout principal (Local).

1

Selecione "Worktree"

Abaixo da caixa de mensagem. Se quiser, escolha um local environment para rodar o setup na worktree.

2

Escolha o branch de partida

main, um branch de feature ou o branch atual, inclusive com alterações não commitadas.

3

Envie o prompt

O Codex cria a worktree e trabalha em detached HEAD por padrão.

4

Decida onde continuar

Continue na worktree ou faça o Handoff para o Local.

Handoff

Move o chat e o código entre Local e Worktree. O Codex cuida das operações de Git, porque o Git só permite um branch em checkout num lugar por vez.

Ficar na worktree

Use Create branch here no cabeçalho do chat. Depois, faça commit, push e abra o PR no GitHub. O botão Open abre a worktree na sua IDE.

Pense no Local como o primeiro plano e na Worktree como o segundo plano, onde você deixa trabalho na fila.
Configuração06

Local environments: setup e actions

Como a worktree roda noutra pasta, ela pode estar sem dependências ou arquivos que não estão no Git. O local environment resolve isso. Ele é configurado nas Settings do app e fica salvo na pasta .codex na raiz do projeto, que você pode versionar para a equipe.

Setup script

Roda automaticamente quando o Codex cria uma nova worktree no início de um chat. Serve para instalar dependências ou fazer o build inicial.

Exemplo: projeto TypeScript
npm install
npm run build
Actions

Tarefas frequentes, como subir o servidor de dev ou rodar os testes, viram botões na barra superior do app e rodam no terminal integrado. Cada action tem um ícone próprio.

Exemplo: action "Run" num projeto Node.js
npm start
Setup e actions aceitam scripts por plataforma (macOS, Windows, Linux) quando os comandos diferem entre sistemas.
A primeira action roda com ⌘+⇧+D no macOS, Win+Shift+D no Windows ou Super+Shift+D no Linux.
Revisão07

Git integrado e terminal

No app você revisa, testa e entrega o trabalho do Codex sem abrir outra ferramenta.

Painel de diff
  • Mostra as mudanças do checkout atual (Local ou Worktree).
  • Aceita comentários inline para o Codex corrigir.
  • Faz stage ou revert de trechos ou de arquivos inteiros.
  • Faz commit, push do branch e cria o pull request.

Painel de revisão: ⌘+⌥+B no macOS ou Ctrl+Alt+B no Windows e no Linux.

Terminal integrado

Cada chat tem um terminal ligado ao seu projeto ou worktree. Abra com Ctrl+` e limpe com Ctrl+L. O Codex lê a saída do terminal, então consegue checar o servidor de dev ou um build que falhou.

git status
git pull --rebase
pnpm test
pnpm run lint
Para operações de Git que o app não oferece (rebase interativo, cherry-pick etc.), use o terminal integrado. Para não misturar mudanças com o seu trabalho, comece a tarefa numa worktree.
Além do código08

Recursos que só o app oferece

O app desktop também deixa o agente usar o navegador e o computador, agendar tarefas e ser controlado pelo celular.

Scheduled tasks

Tarefas agendadas

Rodam em segundo plano de forma recorrente. Em repositórios Git, usam worktrees dedicadas para não conflitar com o seu trabalho. O computador precisa estar ligado e o app aberto quando a tarefa usa arquivos locais.

Codex Remote

Controle pelo celular

No app, vá em Settings → Connections → Control this Mac or PC e escaneie o QR code com o app ChatGPT do celular. Dá para iniciar tarefas, aprovar comandos e revisar diffs à distância, com a execução acontecendo no computador conectado (Mac ou Windows).

Navegador embutido

Testar a aplicação

Abra o painel do navegador com ⌘+⇧+B ou Ctrl+Shift+B para ver o app rodando e comentar direto na página.

Computer Use

Usar outros apps

Permite que o agente use aplicativos do desktop durante a tarefa, sempre dentro das permissões que você concedeu.

A disponibilidade de Remote, navegador e Computer Use depende do sistema, do plano e das configurações do workspace. Alguns recursos ainda estão em rollout gradual.

Fixação10

Teste rápido

1. Você quer que o Codex implemente duas features em paralelo sem mexer nos arquivos que você está editando. Qual modo usar?

A) Local
B) Worktree
C) Full access
D) Quick chat
B. Cada worktree é um checkout isolado do mesmo repositório, e as tarefas rodam em segundo plano sem tocar no seu Local.

2. O que muda ao trocar "Ask for approval" por "Approve for me"?

A) O sandbox é removido
B) O agente ganha acesso à internet
C) Um revisor automático aprova no seu lugar
D) O chat vai para a nuvem
C. O limite do sandbox continua o mesmo. Só muda quem analisa os pedidos para ultrapassá-lo: um agente revisor automático.

3. Onde o Codex salva a configuração do local environment (setup e actions)?

A) Em ~/.bashrc
B) No AGENTS.md
C) Na pasta .codex na raiz do projeto
D) Só na nuvem
C. O arquivo gerado fica em .codex e pode ser versionado no Git para a equipe usar a mesma configuração.

4. No Ubuntu, o que é preciso instalar para o sandbox do Codex funcionar?

A) docker
B) bubblewrap
C) firejail
D) Nada; o sandbox é só no macOS
B. No Linux e no WSL2, o Codex usa o bwrap (sudo apt install bubblewrap). No Ubuntu 24.04 pode ser preciso também o perfil AppArmor.
