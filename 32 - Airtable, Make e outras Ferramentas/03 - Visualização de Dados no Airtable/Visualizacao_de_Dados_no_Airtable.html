Conceito01

Uma tabela, muitas lentes

Uma view (visualização) é um jeito salvo de olhar uma tabela: quais registros aparecem (filtro), em que ordem (ordenação), agrupados como, quais campos e em que formato. Uma tabela pode ter muitas views, de tipos diferentes.

Os dados são os mesmos

Editar um registro numa view muda o registro em todas. Não há cópia.

Filtro esconde, não apaga

Segundo a central de ajuda, um registro filtrado não é excluído: só deixa de aparecer naquela view.

Cada tarefa, uma view

Revisar, planejar, consultar e integrar pedem recortes diferentes. Em vez de mexer no filtro toda hora, crie uma view para cada tarefa.

O contrário também vale: apagar um registro numa view apaga da tabela inteira. Views mudam o que você vê, não o que existe.

Ferramentas03

A barra da view

Hide fields

Esconde colunas que não interessam naquela tarefa. Os dados continuam na tabela.

Filter

Condições que decidem quais registros aparecem, combinadas com "e" / "ou" e em grupos.

Group

Separa os registros em blocos recolhíveis por um campo, com subgrupos.

Sort

Ordena por um ou mais campos. Ordenar por data da mais antiga põe o mais urgente no topo.

Color

Pinta linhas por condição ou por seleção. Não está disponível no plano Free.

Row height e resumo

Altura das linhas (para ler textos longos) e a barra de resumo no rodapé: contagem, soma, preenchidos.

As condições não são só das views: as mesmas condições aparecem nas automações, nas interfaces e nas regras de visibilidade dos formulários. Aprender a filtrar aqui serve para o módulo inteiro.
Passo 104

A view Revisão · Fila

// Filter · Revisão · Fila Where Status is any of Rascunho, Em revisão and Pergunta is not empty // Sort Atualizada em 1 → 9 (mais antiga primeiro) // Hide fields Origem, Revisada
Resultado: só o que falta revisar, com o mais esquecido no topo e só os campos que o revisor usa.
Grupos de condições

Quando precisar misturar "e" e "ou", use um grupo de condições: Categoria = Pagamentos e (Status = Rascunho ou Revisada está desmarcada).

Filtro por vínculo

Campos de vínculo aceitam "has any of": Aula has any of "Usando RAG no Workflow".

Filtros são salvos na view para todo mundo. Mudou o filtro de uma view coletiva? Mudou para a equipe inteira.

Onde dá para agrupar

Segundo a central de ajuda, o agrupamento existe nas views Grid, Timeline, List e Gantt. Os campos mais usados para agrupar são seleção, colaborador, vínculo e data.

O rodapé de cada grupo

Cada grupo pode ter seu resumo: contagem de registros, porcentagem de "Revisada" marcada…

Agrupar por categoria revela onde estão as lacunas: uma categoria só com rascunhos é onde a FAQ mais precisa de trabalho.

Por que revisar respostas publicadas

Preços, planos e prazos mudam. A resposta sobre a taxa do Pix da AbacatePay estava certa em setembro; pode não estar em março. Uma data de revisão evita que a IA repita informação velha.

No Free, o calendário não cria intervalos de datas nem mostra vários campos de data ao mesmo tempo. Um campo de data por view resolve o caso da FAQ.
Passo 508

Galeria e lista

Galeria · "Cartões por aula"

Cada registro vira um cartão. Se houver um campo de anexo (por exemplo, uma captura de tela da aula), ele vira a capa. Bom para quem navega, não para quem edita.

  • Capa: o anexo "Captura"
  • Campos no cartão: Pergunta, Aula, Categoria
  • Filtro: só Publicadas
Lista · "Leitura por categoria"

A view List mostra os registros em linhas compactas e permite aninhar por campos, como um índice: Categoria → Aula → Perguntas.

  • Agrupar por Categoria e, dentro, por Aula
  • Ótima para revisar a FAQ inteira de uma vez
  • Também aceita agrupamento, como a Grid

Formulário público é porta aberta. Qualquer pessoa com o link pode enviar. Não peça CPF nem dados que não vai usar e, se pedir e-mail para responder, diga isso no formulário (LGPD).
No Free, o formulário mantém a marca do Airtable e não aceita imagem de cabeçalho personalizada. Grupos condicionais e outros recursos premium ficam para os planos pagos.
Envios de formulário não contam como colaboradores cobrados nos planos pagos.

Além das views11

Interfaces: uma tela para cada papel

Interface "Painel do Revisor" · reprodução ilustrativa

Views são para quem trabalha na base. Uma interface, feita no Interface Designer, é uma tela montada com componentes (números, listas, detalhes, botões) para quem só precisa fazer uma tarefa.

  • O revisor vê só as perguntas em revisão
  • Lê, comenta e decide com um botão
  • Não vê a estrutura da base nem as outras tabelas
O Omni (aula 01) também monta interfaces a partir de uma descrição. Sempre revise o que ele criou.
Passo 712

A view que o Make vai ler

// View · API · Publicadas (Grid, seção "Integrações") Where Pronta para a IA is Pronta // Sort Categoria A → Z // Campos visíveis Pergunta, Resposta, Categoria, Link da aula
A fórmula "Pronta para a IA" (aula 02) já junta Status, Revisada e Resposta preenchida. A view só precisa de uma condição.
Por que uma view só para a integração

No Make, a busca de registros pode usar uma view: o filtro dela decide o que a automação enxerga. Se alguém mexer no filtro, a automação muda junto. Por isso essa view tem nome claro e, nos planos pagos, fica bloqueada.

Ocultar um campo não é proteção de dados. Quem tem acesso à base (ou um token com acesso a ela) pode ler todos os campos. Dado que a IA não pode ver não deve estar nesta tabela.
Compartilhar13

Links de compartilhamento

Uma view pode ganhar um link de compartilhamento: quem abre vê os registros e campos visíveis daquela view, sem precisar de conta. É um jeito simples de publicar a FAQ para os alunos.

  • Crie uma view só para o link: "Público · FAQ"
  • Filtro: só Publicadas; campos: Pergunta, Resposta, Link da aula
  • Confira o resultado numa janela anônima
  • Desative o link quando não precisar mais
Quem tem o link, vê. Links podem ser encaminhados. Nada de rascunhos, comentários internos ou dados de alunos numa view compartilhada.
Links com restrição (senha ou domínio de e-mail) estão nos planos pagos. No Free, trate todo link compartilhado como público.
Para uma FAQ com cara de site, a interface publicada ou um site próprio (como os do módulo 27, no Lovable) costumam ficar melhores que um link de view.

Armadilhas15

Erros comuns com views

Mexer no filtro da view da API. A automação passa a ler outra coisa, sem avisar ninguém.
Achar que ocultar campo protege. Token e colaboradores leem a tabela inteira.
Arrastar no Kanban sem querer. O cartão mudou de coluna, o Status mudou junto.
Compartilhar a view errada. O link mostrou rascunhos e comentários internos.
Uma view para tudo. Trocar filtros o dia inteiro atrapalha toda a equipe.
Nomes genéricos. "Grid 3" não diz para que serve nem se pode ser alterada.
