O que é
o Airtable

O Airtable parece uma planilha, mas por baixo é um banco de dados: cada coluna tem um tipo, as tabelas se ligam entre si e os mesmos dados aparecem como grade, quadro, calendário ou formulário. Nesta aula, entendemos as peças (base, tabela, campo, registro e visualização), os planos e limites, o que a IA do Airtable faz e quando ele é a ferramenta certa. Também apresentamos o projeto do módulo: a FAQ da Formação, que o Make e a IA vão automatizar nas próximas aulas.

Conceito01

Uma planilha que é banco de dados

Numa planilha, qualquer célula aceita qualquer coisa: um número, uma data escrita de três jeitos, um "ver com o João". No Airtable, cada coluna (campo) tem um tipo, cada linha (registro) é um item e as tabelas podem apontar umas para as outras. A aparência é familiar; a disciplina é de banco de dados.

Fácil como planilha

Você digita, arrasta, filtra e ordena numa grade. Não precisa saber SQL.

Organizado como banco

Campos tipados, listas de opções fixas e vínculos entre tabelas evitam dados repetidos e inconsistentes.

Pronto para automação

Automações internas, formulários, interfaces e uma API para ferramentas como o Make (aula 04).

É esse meio-termo que interessa ao módulo: o Airtable guarda os dados de forma organizada, e ferramentas de automação e IA conseguem ler e escrever nele sem que você precise programar um back-end.

As peças03

Do workspace ao registro

WorkspaceEspaço da equipe. O plano (Free, Team…) é contratado por workspace.
BaseUm projeto, como "FAQ da Formação". Equivale a um banco de dados.
TabelaUm tipo de coisa: Perguntas, Categorias, Aulas.
CampoUma característica, com tipo: texto, data, seleção, vínculo…
RegistroUm item concreto: a pergunta "O que é RLS?".
E a visualização (view)?

É um jeito de olhar uma tabela: com filtro, ordem, campos ocultos e formato (grade, quadro, calendário). Mudar a view não muda os dados.

Regra de bolso

Se você pensaria em "uma aba da planilha", é uma tabela. Se pensaria num "arquivo inteiro", é uma base.

Checkbox; anexos (imagens, PDFs), com limite de armazenamento por plano.

Pessoas

Colaborador, criado por, modificado por.

Link to another record: aponta para registros de outra tabela.

Calculados

Fórmula, lookup (busca no vínculo), rollup (resume o vínculo), contagem.

Escolher o tipo certo é metade do trabalho: "Status" como seleção única garante que ninguém escreva "publicado", "Publicada" e "ok" para a mesma coisa. Isso será essencial quando o Make e a IA lerem a base.
Relacionamentos06

Tabelas que conversam

Em vez de escrever o nome da aula em cada pergunta, a tabela Perguntas tem um campo de vínculo com a tabela Aulas. A aula existe uma vez só; as perguntas apontam para ela.

TabelaCampos principais
PerguntasPergunta, Resposta, Categoria (vínculo), Aula (vínculo), Status
CategoriasNome, Descrição, Perguntas (vínculo de volta)
AulasMódulo, Número, Título, Link, Perguntas (vínculo de volta)
Vínculo de mão dupla

Ao vincular uma pergunta a uma aula, a aula ganha automaticamente a lista das suas perguntas.

Lookup e rollup

Na pergunta, um lookup mostra o link da aula sem copiar nada. Na categoria, uma contagem diz quantas perguntas ela tem.

Mudou o link de uma aula? Você corrige num lugar só, e todas as perguntas passam a mostrar o link novo.

Além da tabela08

O que mais vem junto

Interfaces

Telas montadas com componentes (listas, gráficos, botões) para quem não deve mexer na base. O revisor vê só as perguntas "Em revisão" e um botão "Aprovar".

Automações

"Quando acontecer X, faça Y" dentro do Airtable: avisar por e-mail quando chegar pergunta nova, mudar o status, criar um registro.

Formulários

Páginas públicas que criam registros. Envios de formulário não são cobrados como usuários nos planos pagos.

API e integrações

Leitura e escrita por programas, com tokens de acesso pessoal. É por aí que o Make vai conversar com a base.

As automações internas do Airtable e as do Make se sobrepõem em parte. Regra prática: o que fica dentro da base, automatize no Airtable; o que envolve outros serviços (e-mail, WhatsApp, IA), o Make costuma resolver melhor.
IA09

A IA dentro do Airtable

Omni

O construtor conversacional do Airtable: você descreve o que precisa e ele cria tabelas, interfaces e automações. Também responde perguntas sobre os seus dados.

Field Agents

Campos com IA que executam uma tarefa em cada registro: resumir, classificar, gerar texto, pesquisar e enriquecer dados.

Créditos de IA

O uso é medido em créditos. O plano Free inclui 500; os pagos incluem mais por usuário editor. Pedir ao Omni para construir não tem custo extra; perguntas de análise sobre os dados consomem créditos.

Decisão11

Quando usar e quando não

Bom para
  • Dados de uma equipe que hoje vivem em planilhas bagunçadas
  • Catálogos, CRMs simples, controle de conteúdo, inventários
  • Processos com etapas (rascunho → revisão → publicado)
  • Fonte de dados para automações no Make e protótipos com IA
  • Times sem programador que precisam de formulários e telas
Pense duas vezes
  • Centenas de milhares de registros ou crescimento rápido
  • Aplicativo público com muitos usuários escrevendo ao mesmo tempo
  • Regras de acesso por linha (cada cliente vê só os seus dados): o RLS do Supabase faz isso melhor
  • Dados sensíveis com exigências fortes de onde ficam armazenados
  • Orçamento apertado com muitos editores: o preço é por pessoa
Para a FAQ da Formação, o Airtable é uma ótima escolha: algumas centenas de perguntas, poucos editores, um processo de revisão claro e integração fácil com o Make.

Segurança13

Cuidados desde o começo

Dados pessoais. Nome, e-mail e mensagens de alunos são dados pessoais (LGPD). Guarde só o necessário, diga para que servem e defina por quanto tempo ficam na base.
Tokens de acesso. As antigas chaves de API foram desativadas em 2024. Hoje se usam tokens de acesso pessoal com escopos e bases escolhidos. Dê ao Make só o que ele precisa.
Links de compartilhamento. Um link público de view mostra os dados a quem tiver o endereço. Confira os campos visíveis antes de compartilhar.
Onde os dados ficam. O Airtable é um serviço estrangeiro na nuvem. Para dados sensíveis, verifique as políticas de armazenamento e os contratos antes de usar.
Na FAQ da Formação, a tabela Perguntas guarda a pergunta, não quem perguntou. Se precisar responder alguém, o contato fica numa tabela separada, com acesso restrito.
Armadilhas14

Erros comuns de quem começa

Usar como planilha. Tudo em texto, nada de seleção ou vínculo: a base vira a mesma bagunça, só que mais cara.
Uma tabela gigante. Repetir o nome da aula em cada linha em vez de criar a tabela Aulas e vincular.
Esquecer os limites do Free. 1.000 registros e 1.000 chamadas de API acabam rápido numa automação mal feita.
Token com acesso a tudo. Escopo e bases mínimos; um token por integração.
Confundir view com tabela. Filtrar uma view não apaga nada; apagar um registro apaga em todas.
Mudar o tipo de um campo sem pensar. Converter texto em seleção, por exemplo, pode perder valores fora da lista.

A) Bases
B) Tabelas de uma mesma base
C) Visualizações
D) Workspaces

A) Guardar um link da web
B) Apontar para registros de outra tabela, sem copiar dados
C) Calcular fórmulas
D) Anexar arquivos

Recapitulando

Cara de planilha,
alma de banco de dados

O Airtable organiza dados em workspaces, bases, tabelas, campos e registros. Campos têm tipo, tabelas se vinculam e as views mostram os mesmos dados como grade, quadro, calendário, galeria ou formulário. Interfaces, automações, a API e a IA (Omni e Field Agents) completam o pacote. Vimos os planos e os limites do Free, quando o Airtable é a ferramenta certa, os cuidados com dados pessoais e tokens, e o projeto do módulo: a FAQ da Formação, que o Make e a IA vão automatizar.
