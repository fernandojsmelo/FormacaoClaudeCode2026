Por que uma tabela separada

Perguntas é a FAQ curada: pública, sem dados pessoais. Atendimentos guarda o que chega, com o e-mail do aluno. Separar permite dar acessos diferentes e apagar dados pessoais depois de um tempo (aula 10).

O e-mail só existe para responder. Diga isso no formulário do site e defina por quanto tempo ele fica guardado (LGPD: finalidade e necessidade).
Lembre do limite do Free: 1.000 registros por base, somando Perguntas, Categorias, Aulas e Atendimentos.

Como funciona

O Make cria um endereço. Quem envia um POST para ele entrega um bundle ao cenário. Segundo a central de ajuda, cada webhook tem a sua fila: as requisições ficam guardadas até serem processadas.

Sem o módulo de resposta, o Make devolve 200 Accepted; com a fila cheia, 400; com excesso de chamadas, 429 Too many requests. O site precisa tratar esses casos.

Segurança05

Trancar a porta

A URL do webhook é pública por natureza: quem a descobrir pode mandar perguntas falsas, gastar seus créditos e encher a base. Uma proteção simples: exigir um token secreto num cabeçalho e filtrar.

// Filtro logo após o webhook · "Token confere" Condição 1. Headers[] → x-faq-token Text operators: Equal to (case sensitive) <token guardado num lugar seguro>
  • O token fica no servidor do site (por exemplo, numa função de back-end ou edge function), nunca no JavaScript do navegador
  • Requisição sem token não passa do filtro: nada é gravado
  • Troque o token se desconfiar de vazamento
  • Limite o tamanho da pergunta no site (ex.: 1.000 caracteres)
O gatilho ainda consome 1 crédito por requisição, mesmo barrada. Para ataques em volume, a proteção precisa estar também antes do Make: captcha e limite de envios no site.

A saída deste módulo traz o ID do registro criado (rec…). As próximas aulas usam esse ID para atualizar o mesmo atendimento.

Passo 407

Responder ao site

// Webhooks · Webhook response Status: 200 Body: { "ok": true, "mensagem": "Recebemos sua pergunta. A resposta chega por e-mail." } Custom headers: Content-Type: application/json
A central de ajuda recomenda ajustar o Content-Type ao formato do corpo: com JSON, application/json.
Por que responder já

A IA e a revisão podem levar minutos ou horas. O aluno precisa saber, na hora, que a pergunta chegou e como a resposta vai chegar.

E se o token não conferir?

Adicione uma segunda rota (com Router) que responde 401 e {"ok": false}. Sem isso, o site recebe o "Accepted" padrão e acha que deu certo.

A resposta não deve conter o ID interno nem dados de outros alunos. Só o necessário para o site mostrar a mensagem.

Integração10

Ligar o site

// No back-end do site (ex.: função serverless) const r = await fetch(process.env.MAKE_FAQ_WEBHOOK, { method: "POST", headers: { "Content-Type": "application/json", "X-FAQ-Token": process.env.FAQ_TOKEN, }, body: JSON.stringify({ pergunta: texto.slice(0, 1000), email, origem: "site", }), }); if (!r.ok) /* mostrar "tente de novo em instantes" */
Onde fica o código

No back-end: uma edge function do Supabase (módulo 28), uma rota de API ou uma função serverless. URL e token vêm de variáveis de ambiente.

Nunca chame o webhook direto do navegador com o token no código: qualquer visitante veria o token ao abrir as ferramentas do desenvolvedor.
Um site feito no Lovable (módulo 27) com Supabase (módulo 28) é um ótimo "rosto" para esta FAQ.

Armadilhas12

Erros comuns na entrada

Webhook sem token. Qualquer um envia perguntas falsas e gasta seus créditos.
Token no JavaScript do navegador. É o mesmo que publicá-lo.
Chamar a IA antes de gravar. Se a IA falhar, a pergunta some.
Sem Webhook response. O site recebe "Accepted" até quando algo deu errado.
E-mail do aluno na FAQ pública. Dados pessoais ficam só em Atendimentos.
Testar com e-mails de verdade de alunos. Use o seu.
