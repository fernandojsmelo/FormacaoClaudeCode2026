Funcionalidades de IA e MCP no Cursor · Aula 5

O que é
o MCP

O Model Context Protocol é um padrão aberto para conectar aplicações de IA a sistemas externos: arquivos, bancos de dados, APIs, ferramentas e fluxos de trabalho. É o que deixa o agente do Cursor consultar o GitHub, controlar um navegador ou ler o seu banco sem você copiar e colar nada. Nesta aula: o problema que ele resolve, o que um servidor MCP oferece e como isso aparece no Cursor.

O problema01

Cada IA com cada ferramenta: integração demais

Sem um padrão, cada aplicação de IA precisa de uma integração própria para cada ferramenta: o editor A fala com o GitHub de um jeito, o editor B de outro, e assim por diante. Com N aplicações e M ferramentas, são N × M integrações para escrever e manter.

Sem padrãoCom MCP
4 apps × 5 ferramentas20 integrações4 clientes + 5 servidores = 9
Nova ferramentaUma integração por appUm servidor MCP, serve para todos
Novo app de IAUma integração por ferramentaFala MCP e usa todos os servidores
E para quem usa?

Sem integração, sobra o trabalho manual: copiar a issue do GitHub, colar o resultado da consulta no banco, descrever o que aparece no navegador. A documentação do Cursor resume: em vez de explicar a estrutura do projeto repetidas vezes, integre diretamente com as suas ferramentas.

Definição02

Um padrão aberto, como o USB-C

"MCP (Model Context Protocol) é um padrão de código aberto para conectar aplicações de IA a sistemas externos." — modelcontextprotocol.io
A analogia oficial

Pense no MCP como uma porta USB-C para aplicações de IA. Assim como o USB-C padroniza a ligação entre aparelhos eletrônicos, o MCP padroniza a ligação entre aplicações de IA e sistemas externos.

Quem ganha04

Por que o MCP importa

Desenvolvedores

Menos tempo e complexidade para construir uma aplicação de IA ou integrar com uma. Um servidor escrito uma vez funciona em vários clientes.

Aplicações e agentes

Acesso a um ecossistema de fontes de dados, ferramentas e apps, que aumenta o que eles conseguem fazer.

Usuários finais

Assistentes mais capazes, que acessam seus dados e agem em seu nome quando necessário.

Suporte amplo

Assistentes como Claude e ChatGPT, ferramentas de desenvolvimento como Visual Studio Code e Cursor, e muitos outros suportam MCP. A ideia, nas palavras do site oficial: construa uma vez e integre em todo lugar.

Servidores MCP podem ser escritos em qualquer linguagem que consiga escrever no stdout ou servir um endpoint HTTP: Python, JavaScript, Go e outras. Há SDKs oficiais para C#, Go, Java, Kotlin, PHP, Python, Ruby, Rust, Swift e TypeScript.

SistemaGitHub, banco, navegador, arquivos…
Servidor MCP

É o programa que expõe ferramentas e dados para o Cursor pelo protocolo. O agente chama essas ferramentas durante a conversa. Pode rodar na sua máquina ou em outro lugar, na internet.

Cliente MCP

Fica dentro da aplicação de IA e mantém a conexão com um servidor. O Cursor cria um cliente para cada servidor configurado. Os detalhes da arquitetura são a aula 06.

O que oferece06

Tools, resources e prompts

Tools (ferramentas)

Funções que a IA pode executar para agir: operações em arquivos, chamadas de API, consultas ao banco.

Resources (recursos)

Fontes de dados que dão contexto: conteúdo de arquivos, registros do banco, respostas de API.

Prompts

Modelos de mensagem reutilizáveis que estruturam a interação com o modelo, como exemplos de uso.

Exemplo da documentação: um servidor de banco de dados

Expõe tools para consultar o banco, um resource com o esquema das tabelas e um prompt com exemplos de como usar as ferramentas.

Na prática, no Cursor, as tools são o que mais aparece: o agente decide sozinho quando chamar cada uma, do mesmo jeito que escolhe ler um arquivo ou rodar um comando. O Cursor também suporta resources, prompts e outros recursos do protocolo.

No Cursor08

Como o MCP aparece no Cursor

1
Instalar: pela página Customize (barra lateral) › MCPs, com um clique, ou escrevendo um mcp.json.
2
Usar: o agente usa as ferramentas listadas em Available Tools quando forem relevantes, inclusive no modo Plan. Você também pode pedir pelo nome.
3
Aprovar: por padrão, o Cursor pede aprovação antes de usar uma ferramenta MCP; a seta ao lado do nome mostra os argumentos. MCP segue os mesmos Run Modes dos comandos de terminal.
4
Ligar e desligar: em Customize, cada servidor tem uma chave; desligado, ele não carrega nem aparece no chat.
.cursor/mcp.json · exemplo de servidor local
{
  "mcpServers": {
    "server-name": {
      "command": "npx",
      "args": ["-y", "mcp-server"],
      "env": { "API_KEY": "value" }
    }
  }
}
Exemplo de servidor remoto
{
  "mcpServers": {
    "server-name": {
      "url": "http://localhost:3000/mcp",
      "headers": { "API_KEY": "value" }
    }
  }
}
Custo de contexto09

Mais servidores não é melhor

Cada servidor ligado traz suas instruções e o catálogo de ferramentas para a janela de contexto (categoria "MCP" no anel de contexto, visto no módulo 35). Muitos servidores = muitas ferramentas para o modelo escolher e menos espaço para o seu código.

  • Ligue só os servidores que o projeto usa
  • Desligue o resto em Customize, sem remover
  • Prefira servidores que deixam escolher conjuntos de ferramentas
Projeto ou global?

.cursor/mcp.json na pasta do projeto vale só ali e pode ir para o Git, para o time ter as mesmas ferramentas. ~/.cursor/mcp.json vale em todos os projetos. Os dois são combinados; com o mesmo nome, o do projeto vence.

Se o mcp.json do projeto vai para o Git, não coloque tokens nele. Use variáveis como ${env:API_KEY} (aula 08).
Segurança10

Um servidor MCP age em seu nome

A documentação do Cursor lembra: servidores MCP podem acessar serviços externos e executar código em seu nome. Entenda o que um servidor faz antes de instalar.
  • Verifique a origem: só instale de desenvolvedores e repositórios confiáveis
  • Revise as permissões: que dados e APIs o servidor vai acessar
  • Limite as chaves: tokens com o mínimo de permissão necessário
  • Audite o código: em integrações críticas, leia o código do servidor
Segredos

Use variáveis de ambiente para chaves e tokens; nunca escreva o valor direto em arquivos versionados.

Aprovação

Mantenha a aprovação das ferramentas MCP ligada no começo. Libere automaticamente só as ferramentas de leitura em que você confia.

Injeção de prompt

Conteúdo vindo de fora (uma issue, uma página web) pode tentar dar ordens ao agente. Desconfie de ações que você não pediu.

Encerramento · Funcionalidades de IA e MCP no Cursor

Um protocolo,
muitas ferramentas

O MCP troca N × M integrações por um padrão comum. Servidores oferecem tools, resources e prompts; rodam localmente (stdio) ou remotamente (HTTP). No Cursor, instale pelo Customize ou pelo mcp.json, ligue só o que usa e trate cada servidor como alguém agindo em seu nome.
