Funcionalidades de IA e MCP no Cursor · Aula 3

Utilizando o Ask para
compreensão de código

O Ask é o modo somente leitura do Agent: ele busca, lê e explica o código, mas não edita nada. É o modo certo para chegar num projeto novo, entender um fluxo antes de mexer e tirar dúvidas sem risco. Nesta aula: como ativar, que perguntas fazer, como dar contexto e como passar da compreensão para a mudança.

Conceito01

O que é o modo Ask

A ajuda do Cursor define: o Ask é um modo somente leitura para entender o projeto. O agente responde e explora o código sem fazer edições.

Ele continua sendo um agente

Tem as mesmas ferramentas de busca e leitura do Agent: procura por nome, por texto e pelo significado, lê os arquivos que importam e monta a resposta com referências. Só não edita.

  • Ideal para entender antes de mudar
  • Seguro para explorar um projeto que você não conhece
  • As rules do projeto, do usuário e do time valem também no Ask
  • Cada modo tem o próprio contexto: trocar de modo começa uma janela nova
Quando a pergunta virar pedido de mudança, a própria ajuda orienta: volte para o modo Agent.
Na prática02

Como ativar

1
Abra o painel do Agent: Ctrl + I no Windows e no Linux, Cmd + I no macOS.
2
Mude para Ask: Shift + Tab alterna entre os modos; ou use o seletor de modo no campo do chat.
3
Escreva a pergunta (ou dite, como na aula 02) e tecle Enter.

Roteiro05

Chegando num projeto novo

1
Mapa: "Resuma este projeto: objetivo, tecnologias, pastas principais e como rodar."
2
Entrada: "Por onde a aplicação começa? Mostre o caminho de uma requisição típica."
3
Dados: "Quais são as entidades principais e onde ficam os modelos e o acesso ao banco?"
4
Padrões: "Que convenções este projeto segue para erros, testes e nomes?"
5
Riscos: "Que partes parecem frágeis ou sem testes?"
Peça para o Ask salvar o mapa num arquivo? Não dá: ele não edita. Copie a resposta para um NOTAS.md ou, depois, peça ao Agent para criar um AGENTS.md a partir do que vocês descobriram.
Para buscas muito amplas, o agente pode usar o subagente Explore, que faz várias buscas em paralelo num contexto próprio e devolve só o resumo.

Exemplo com trecho selecionado
[trecho selecionado de auth.ts] Por que este trecho compara o hash mesmo quando o usuário não existe? Isso é proposital?
Use @ quando souber onde está o assunto; quando não souber, deixe o Ask buscar. Ele procura por nome, texto exato e significado.
Revisão07

Ask para revisar mudanças

O Ask também é útil depois que o código mudou, seu ou do agente: ele lê o diff e explica sem risco de mexer em nada.

Explique em linguagem simples o que mudou em @Commit. Aponte qualquer coisa que pareça um bug ou um caso não tratado.
Compare @Branch com a main: que arquivos foram alterados e qual o risco de cada mudança?
Para uma revisão de código dedicada, o Cursor tem o Agent Review (/agent-review, aula 01), com profundidade Quick ou Deep.
O Ask é bom para entender um diff; o Agent Review é feito para caçar problemas. Os dois se completam.
Transição08

Do Ask para a mudança

AskEntenda o fluxo e onde mexer
ResumoPeça um resumo curto do que descobriu
TrocaMude para Agent ou Plan
PedidoCole o resumo + o que fazer
MudançaCom contexto certo desde o início
Lembre: trocar de modo começa um contexto novo. O que o Ask leu não vai junto automaticamente; leve o resumo ou cite a conversa com @Chats.
Mudança grande ou em vários arquivos? Prefira o Plan: você revisa a abordagem antes de qualquer edição.
Resuma em 5 linhas o fluxo de login e os arquivos envolvidos, para eu usar como contexto num pedido de mudança.
Boas práticas09

Perguntando bem

  • Uma pergunta por vez, do geral para o específico
  • Diga por que quer saber ("vou mudar a regra de frete")
  • Peça referências: arquivo e linhas de cada afirmação
  • Peça exemplos de entrada e saída para funções confusas
  • Conversa nova para um assunto novo
  • Confira as referências abrindo os arquivos citados
  • Desconfie de respostas sem referência: peça "mostre onde está isso"
  • Para dúvida paralela, use um side chat (/side)
  • Use o Ask para estudar uma biblioteca nova dentro do seu projeto
  • Guarde o que aprendeu num arquivo do projeto
O Ask pode errar ou inventar um detalhe, como qualquer modelo. A vantagem é que ele mostra de onde tirou a resposta: sempre confira na fonte o que for importante.
Exercício10

Entenda um projeto que não é seu

1
Clone um projeto pequeno de código aberto, na linguagem que você conhece.
2
No modo Ask, faça as cinco perguntas do roteiro da seção 05.
3
Escolha uma função confusa, selecione e pergunte com Ctrl + Shift + L.
4
Abra dois arquivos citados e confira se a resposta bate.
5
Escreva um NOTAS.md com o mapa do projeto, com suas palavras.
Ao final, rode git status: nenhum arquivo do projeto deve ter mudado além do seu NOTAS.md. É a prova de que o Ask não edita.
Dica: faça a mesma pergunta no Ask com modelos diferentes e compare a qualidade das referências.
Quiz de fixação11

Teste o que ficou

1. O que caracteriza o modo Ask?

A) Edita sem pedir aprovação
B) Responde e explora o código sem editar
C) Só funciona offline
D) Não lê arquivos
B. É o modo somente leitura.

2. Como trocar para o Ask pelo teclado?

A) Ctrl + K
B) Shift + Tab
C) Ctrl + Shift + L
D) Alt + A
B. Shift + Tab alterna entre os modos.

3. Você entendeu o fluxo no Ask e mudou para Agent. O que o Agent já sabe da conversa?

A) Tudo
B) Nada automaticamente: o contexto é novo
C) Só os arquivos abertos
D) Só as rules
B. Leve um resumo ou use @Chats.

4. As rules do projeto valem no modo Ask?

A) Não
B) Sim, em todos os modos
C) Só as do usuário
D) Só com MCP
B. Agent, Ask, Plan e Debug.
Encerramento · Funcionalidades de IA e MCP no Cursor

Entender primeiro,
mudar depois

O Ask busca, lê e explica sem editar nada. Ative com Shift + Tab, siga um roteiro de perguntas do geral para o específico, aponte o contexto com @ e seleção, confira as referências e leve um resumo quando for a hora de mudar, no Agent ou no Plan.
