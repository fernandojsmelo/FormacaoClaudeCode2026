O Customize faz mais

A mesma página reúne plugins, skills, rules, subagentes, comandos e hooks, com filtro por escopo: só você, o workspace ou o time. Também mostra um ranking dos mais usados no time e na comunidade.

Pronto: o servidor está conectado e o agente usa as ferramentas quando forem relevantes. Confira na lista de ferramentas do chat.
Em times, os admins podem distribuir servidores por um marketplace do time; eles aparecem no Customize junto com os seus.
Comunidade04

cursor.directory e o botão Add to Cursor

A documentação do Cursor indica o cursor.directory para plugins e servidores MCP da comunidade. Lá, cada servidor traz a configuração pronta e, muitas vezes, um botão de instalação.

Como funciona o botão

Botões "Add to Cursor" (em sites e READMEs) são deeplinks: abrem o Cursor com a configuração do servidor já preenchida, para você confirmar. O formato é cursor.com/en/install-mcp?name=…&config=…, com a configuração em base64.

Exemplo: o botão do Playwright MCP traz esta configuração
{
  "command": "npx @playwright/mcp@latest"
}
O botão facilita, mas não verifica nada por você. Antes de confirmar, leia o comando ou a URL que vai entrar no seu mcp.json.
Comunidade = qualidade variável. Prefira servidores com repositório público, documentação e manutenção recente.
Catálogo oficial05

O MCP Registry

O repositório oficial do MCP orienta: para uma lista de servidores, use o MCP Registry em registry.modelcontextprotocol.io. Ele tem busca no site e uma API pública.

CampoExemplo
nameio.github.github/github-mcp-server
versionCada versão publicada é um registro
packagesoci: ghcr.io/github/github-mcp-server · npm: @playwright/mcp · pypi: …
remotesstreamable-http + URL, para servidores remotos
Buscando pela API
curl "https://registry.modelcontextprotocol.io/v0/servers?search=playwright"
Leia o nome de trás para frente

O nome começa pelo dono, em formato de domínio invertido: io.github.microsoft/… é publicado pela conta microsoft do GitHub; com.empresa/…, pelo domínio empresa.com. É a pista mais rápida para separar o oficial da cópia.

Na prática06

Muitos resultados, poucos oficiais

Buscar "github" no Registry (outubro de 2026) devolve dezenas de servidores: integrações com o Obsidian, analisadores de PR, raspadores de repositórios, proxies de terceiros… O oficial do GitHub é um só:

Nome no RegistryPublicador
io.github.github/github-mcp-serverConta github (oficial)
io.github.microsoft/playwright-mcpConta microsoft (oficial)
com.algumproxy/github-mcp-serverTerceiro, com o mesmo nome no final
Um servidor com nome parecido pode ser um proxy de terceiro: o seu token do GitHub passaria pelo servidor de outra pessoa. Confira sempre o publicador.
A terceira linha da tabela é um exemplo genérico, para mostrar o padrão de nome.
Regra de bolso: para um serviço conhecido, comece pelo Marketplace do Cursor ou pelo site e GitHub do próprio fornecedor.

Manual08

Instalando pelo mcp.json

ArquivoVale para
.cursor/mcp.jsonSó este projeto; pode ir para o Git e o time recebe as mesmas ferramentas
~/.cursor/mcp.jsonTodos os seus projetos
Os dois arquivos são combinados. Se o mesmo nome aparecer nos dois, vale o do projeto.
Depois de salvar o arquivo, reinicie o Cursor para carregar o servidor.
Exemplo: servidor de referência Fetch (local, Python)
{
  "mcpServers": {
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    }
  }
}
Exemplo: servidor remoto com token
{
  "mcpServers": {
    "meu-servico": {
      "url": "https://mcp.exemplo.com/mcp",
      "headers": {
        "Authorization": "Bearer ${env:MEU_TOKEN}"
      }
    }
  }
}
Critérios09

Como avaliar um servidor

  • Quem publica? O fornecedor do serviço, uma empresa conhecida ou um anônimo?
  • Código aberto? Dá para ler o que ele faz com seus dados?
  • Mantido? Versões recentes, issues respondidas, documentação clara
  • Local ou remoto? Remoto de terceiro = seus dados passam por outro servidor
  • Que permissões pede? Leitura basta? Existe modo somente leitura?
  • Quantas ferramentas? Dá para escolher só o conjunto que você usa?
  • Como autentica? OAuth é preferível a colar tokens longos
  • Precisa de quê? Node, Python, Docker instalados na máquina
Lembrete da documentação do Cursor: servidores MCP podem acessar serviços externos e executar código em seu nome. Instale só de fontes confiáveis e, em integrações críticas, leia o código.
Conferência10

Instalou? Confira

1
Em Customize › MCPs, o servidor aparece na lista de instalados e com a chave ligada.
2
No chat, a lista de ferramentas no topo do painel mostra as dele; clique no nome de uma para ligar ou desligar.
3
Peça algo simples que use o servidor e veja o pedido de aprovação com os argumentos.
4
Se não funcionar: Output (Ctrl + Shift + U; Cmd + Shift + U no macOS) › MCP Logs.
Problemas comuns
  • JSON inválido: vírgula sobrando ou faltando; valide o arquivo
  • Comando não encontrado: falta Node (npx), Python/uv (uvx) ou Docker
  • Variável vazia: o Cursor não enxerga variáveis do seu shell; reinicie o Cursor depois de mudar o perfil
  • Versão antiga presa: remova, limpe o cache (npm cache clean --force) e adicione de novo
Exercício11

Garimpando servidores

1
Abra Customize › MCPs e liste três servidores oficiais úteis para o seu trabalho.
2
Busque "postgres" no MCP Registry e anote quem publica os três primeiros resultados.
3
Instale o servidor de referência Time ou Fetch num .cursor/mcp.json de teste.
4
Peça ao agente: "que horas são agora em Tóquio?" (Time) ou "resuma a página X" (Fetch) e aprove a chamada.
5
Desligue o servidor e repita o pedido: veja a diferença.
O servidor Time roda com uvx mcp-server-time e não precisa de chave: é o mais simples para um primeiro teste.
