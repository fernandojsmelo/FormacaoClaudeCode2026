MCP do GitHub

O servidor MCP oficial do GitHub deixa o agente do Cursor ler repositórios, cuidar de issues e pull requests e acompanhar o GitHub Actions, tudo pelo chat. Nesta aula: os três jeitos de instalar, como criar um token com o mínimo de permissão, como escolher os conjuntos de ferramentas, como testar e como usar com segurança.

Conceito01

O que o servidor do GitHub faz

O GitHub MCP Server conecta ferramentas de IA direto à plataforma do GitHub: ler repositórios e arquivos, gerenciar issues e PRs, analisar código e automatizar fluxos, tudo em linguagem natural.

UsoExemplos
RepositóriosBuscar código e arquivos, analisar commits, entender a estrutura
Issues e PRsCriar, atualizar, triar bugs, revisar mudanças
CI/CDAcompanhar o GitHub Actions, analisar falhas de build
SegurançaAlertas do Dependabot e do code scanning
TimeDiscussões, notificações, atividade
MCP do GitHub × Git no terminal

O agente já sabe usar o git no terminal para o repositório local (commit, branch, diff). O MCP do GitHub fala com o github.com: issues, PRs, Actions, código de outros repositórios. Os dois se completam.

O pacote npm antigo @modelcontextprotocol/server-github não é mais suportado desde abril de 2025. Tutoriais antigos ainda o usam; ignore-os.

Caminho B · passo 104

Criando o token (PAT)

1
No GitHub: Settings › Developer settings › Personal access tokens › Fine-grained tokens (ou direto em github.com/settings/personal-access-tokens/new).
2
Dê um nome claro ("cursor-mcp") e uma validade curta, como 30 ou 90 dias.
3
Em Repository access, escolha Only select repositories e marque só os do curso.
4
Em Permissions, libere só o que vai usar (tabela ao lado).
5
Gere e copie o token na hora: o GitHub não mostra de novo.
Permissão do repositórioPara
Metadata · leituraObrigatória (já vem marcada)
Contents · leituraLer arquivos e código
Issues · leitura e escritaListar, criar e comentar issues
Pull requests · leitura e escritaListar, criar e revisar PRs
Actions · leituraVer execuções e logs de CI
O README do servidor avisa: ele usa muitas APIs do GitHub, então libere só as permissões com que você se sente à vontade em dar a uma IA. Para só consultar, use tudo em leitura.
Caminho B · passo 205

Configurando o servidor remoto

~/.cursor/mcp.json · como no guia do GitHub
{
  "mcpServers": {
    "github": {
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "Authorization": "Bearer YOUR_GITHUB_PAT"
      }
    }
  }
}
Melhor: o token numa variável de ambiente
"headers": {
  "Authorization": "Bearer ${env:GITHUB_PAT}"
}
1
Abra (ou crie) ~/.cursor/mcp.json, o arquivo global.
2
Cole a configuração. Use ${env:GITHUB_PAT} e defina a variável no sistema.
3
Salve e reinicie o Cursor por completo.
O guia também oferece um botão de instalação que preenche isso; depois é só trocar YOUR_GITHUB_PAT pelo token. O transporte é Streamable HTTP (Cursor 0.48 ou mais novo).
Prefira o arquivo global. O .cursor/mcp.json do projeto costuma ir para o Git, e um token ali vaza junto.
Variável de ambiente06

Definindo GITHUB_PAT em cada sistema

SistemaComo definir (permanente para o seu usuário)
WindowsPowerShell: setx GITHUB_PAT "seu_token" · ou Configurações › Sistema › Sobre › Configurações avançadas › Variáveis de Ambiente
macOSNo ~/.zshrc: export GITHUB_PAT="seu_token" · abra o Cursor a partir de um terminal novo, ou reinicie a sessão
LinuxNo ~/.bashrc ou ~/.zshrc: export GITHUB_PAT="seu_token" · faça logout e login para valer em apps abertos pelo menu
A ajuda do Cursor avisa: se o servidor depende de variáveis definidas no perfil do shell, elas precisam estar disponíveis para o Cursor. Depois de mudar o perfil, reinicie o Cursor.
Para servidores locais (stdio), dá também para usar "envFile": ".env". Servidores remotos não aceitam envFile: use ${env:…}.
Caminho C07

Servidor local com Docker

Com login OAuth (sem token para guardar)
{
  "mcpServers": {
    "github": {
      "command": "docker",
      "args": ["run", "-i", "--rm",
        "-p", "127.0.0.1:8085:8085",
        "-e", "GITHUB_OAUTH_CALLBACK_PORT",
        "ghcr.io/github/github-mcp-server"],
      "env": { "GITHUB_OAUTH_CALLBACK_PORT": "8085" }
    }
  }
}
Como funciona

No github.com, a imagem oficial já traz as credenciais do app: no primeiro uso abre um login no navegador e o token fica só na memória. A porta fixa 8085 recebe o retorno do login.

Ou com PAT (tem prioridade sobre o OAuth)
"args": ["run", "-i", "--rm", "-e",
  "GITHUB_PERSONAL_ACCESS_TOKEN",
  "ghcr.io/github/github-mcp-server"],
"env": { "GITHUB_PERSONAL_ACCESS_TOKEN":
         "${env:GITHUB_PAT}" }
O Docker Desktop (ou o Docker Engine, no Linux) precisa estar rodando. Erro ao baixar a imagem: tente docker logout ghcr.io.

Ajuste fino09

Toolsets e modo somente leitura

O servidor tem perto de cem ferramentas, agrupadas em toolsets. Sem configuração, vem o conjunto default:

contextreposissuespull_requestsusers
No servidor remoto, use a URLResultado
…/mcp/Toolsets padrão
…/mcp/readonlyPadrão, só ferramentas de leitura
…/mcp/x/actionsSó GitHub Actions
…/mcp/x/issues/readonlySó issues, só leitura
…/mcp/x/allTodos os toolsets
Outros toolsets

actions, code_security, dependabot, discussions, gists, labels, notifications, orgs, projects, secret_protection, security_advisories, stargazers e outros.

Menos ferramentas = menos contexto ocupado e menos chance de o agente escolher a ferramenta errada. Comece com readonly e libere escrita quando precisar.
No servidor local, o equivalente é GITHUB_TOOLSETS="default,actions" e GITHUB_READ_ONLY=1 nas variáveis do Docker.
Na prática10

Pedidos que usam o GitHub

Triagem
Liste as issues abertas com o rótulo bug em fernando/todo-app e ordene por quantidade de comentários. Resuma cada uma em uma linha.
Da issue ao PR
Leia a issue #14, corrija o problema numa branch nova, rode os testes e abra um pull request que cite a issue. Não faça merge.
CI
A última execução do GitHub Actions falhou. Leia os logs do job que quebrou e me diga a causa provável, sem mudar nada ainda.
Revisão
Leia o PR #22 e deixe um comentário de revisão com riscos e sugestões. Não aprove nem feche.
Diga sempre até onde o agente pode ir ("não faça merge", "sem mudar nada ainda"). Ações no GitHub são visíveis para o time.
Segurança11

Usando com segurança

  • Token fine-grained, só nos repositórios necessários e com validade curta
  • Nunca deixe o token num arquivo que vai para o Git
  • Comece com readonly; libere escrita por toolset
  • Mantenha a aprovação das ferramentas de escrita (criar, comentar, fazer merge)
  • Coloque na allowlist só ferramentas de leitura que você usa sempre
  • Desconfie de issues e PRs de terceiros: o texto pode tentar dar ordens ao agente (injeção de prompt)
  • Revogue o token no GitHub se ele vazar ou não for mais usado
  • Para organizações, veja se há aprovação de tokens pelos admins
Modo lockdown: em repositórios públicos, o servidor só mostra conteúdo (issues, PRs, comentários) de quem tem permissão de push, reduzindo o risco de injeção de prompt. É um filtro de melhor esforço, não uma barreira de permissão. Local: GITHUB_LOCKDOWN_MODE=1; remoto: cabeçalho X-MCP-Lockdown.
Problemas comuns12

Quando não conecta

Sem ponto verde

Reinicie o Cursor por completo e valide o JSON (vírgulas, aspas).

401 · não autorizado

Token errado, expirado ou variável vazia. Teste o token e reinicie o Cursor depois de definir a variável.

403 · sem permissão

Falta a permissão no token ou o repositório não foi selecionado no fine-grained.

Ferramentas não aparecem

Servidor desligado em Customize, ou toolset sem a ferramenta (por exemplo, readonly não tem escrita).

Docker

Docker parado ou não instalado. Abra o Docker Desktop e tente de novo.

Rede

Proxy ou firewall da empresa bloqueando api.githubcopilot.com. Fale com o time de TI.

Em todos os casos, o primeiro lugar para olhar é Output › MCP Logs (Ctrl + Shift + U).
