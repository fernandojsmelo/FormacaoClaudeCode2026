Modelo de dados02

Uma tarefa deixa de ser só um texto

Para guardar se a tarefa está feita, cada item da lista vira um dicionário. Essa é a mudança que puxa todas as outras:

v1 · lista de textos
["Estudar MCP", "Revisar o PR #22"]
v2 · lista de dicionários
[{"id": 1, "texto": "Estudar MCP", "concluida": True},
 {"id": 2, "texto": "Revisar o PR #22", "concluida": False}]
Por que um id

O id identifica a tarefa para sempre, mesmo que ela mude de posição na lista. Vai ser a chave dos botões e checkboxes (seção 07 explica por que isso importa).

Peça ao agente para propor o modelo de dados primeiro. É mais fácil discutir três campos do que revisar cinquenta linhas de código.

Código04

Adicionar com id

# Cada tarefa agora é um dicionário: id fixo, texto e se está concluída.
if "tarefas" not in st.session_state:
    st.session_state.tarefas = []
    st.session_state.proximo_id = 1

with st.form("nova_tarefa", clear_on_submit=True):
    col_texto, col_botao = st.columns([4, 1], vertical_alignment="bottom")
    texto = col_texto.text_input("Nova tarefa", placeholder="O que você precisa fazer?")
    adicionar = col_botao.form_submit_button("Adicionar", width="stretch")

if adicionar:
    texto = texto.strip()
    if not texto:
        st.warning("Digite uma tarefa antes de adicionar.")
    else:
        st.session_state.tarefas.append(
            {"id": st.session_state.proximo_id, "texto": texto, "concluida": False}
        )
        st.session_state.proximo_id += 1
  • proximo_id é um contador guardado na sessão; cada tarefa nova pega o próximo número
  • O id nunca é reaproveitado, mesmo depois de remover
  • Toda tarefa nasce com "concluida": False
  • O aviso de tarefa vazia e o formulário continuam iguais à v1
Ao revisar o diff, procure o que não mudou: se o agente mexeu em algo que já funcionava sem motivo, pergunte por quê.
Código05

Progresso, filtro e checkboxes

concluidas = sum(t["concluida"] for t in tarefas)
st.progress(concluidas / len(tarefas), text=f"{concluidas} de {len(tarefas)} concluída(s)")

filtro = st.radio("Mostrar", ["Todas", "Pendentes", "Concluídas"], horizontal=True)
visiveis = [
    t for t in tarefas
    if filtro == "Todas"
    or (filtro == "Pendentes" and not t["concluida"])
    or (filtro == "Concluídas" and t["concluida"])
]
if not visiveis:
    st.caption("Nenhuma tarefa neste filtro.")

# As chaves usam o id da tarefa, não a posição: assim, remover uma tarefa
# não faz a de baixo "herdar" o checkbox marcado.
for tarefa in visiveis:
    col_check, col_remover = st.columns([5, 1], vertical_alignment="center")
    rotulo = f"~~{tarefa['texto']}~~" if tarefa["concluida"] else tarefa["texto"]
    marcada = col_check.checkbox(rotulo, value=tarefa["concluida"], key=f"feita_{tarefa['id']}")
    if marcada != tarefa["concluida"]:
        tarefa["concluida"] = marcada
        st.rerun()
    if col_remover.button("Remover", key=f"remover_{tarefa['id']}"):
        tarefas.remove(tarefa)
        st.rerun()

if concluidas and st.button("Limpar concluídas"):
    st.session_state.tarefas = [t for t in tarefas if not t["concluida"]]
    st.rerun()
sum() conta as concluídas, porque True vale 1.
~~texto~~ é Markdown: o Streamlit mostra riscado.
st.rerun() redesenha na hora, com o progresso atualizado.

Bug07

O bug que quase passou

Na primeira tentativa, o código da v2 usava a posição da tarefa como chave do checkbox, como a v1 fazia com o botão Remover:

for i, tarefa in enumerate(tarefas):
    ... st.checkbox(..., key=f"feita_{i}")
1
Adicione A e B. Marque A como concluída.
2
Remova A. Agora B está na posição 0.
3
O Streamlit lembra que o checkbox feita_0 estava marcado… e B aparece concluída sem ninguém ter clicado.
Por que acontece: o Streamlit guarda o estado de cada widget pela chave. Se a chave depende da posição, o estado "passa" para quem ocupar aquela posição.
Correção: chave pelo id da tarefa (feita_{tarefa['id']}). O id não muda quando a lista muda.
Esse bug não aparece num teste "feliz" (adicionar, marcar, ver riscado). Só aparece quando você remove depois de marcar. Por isso vale testar combinações.
Método08

Pegando bugs com o agente

1 · Descreva o sintoma, com passos
Bug: marquei A como concluída, removi A, e a tarefa B apareceu concluída sozinha. Passos: adicionar A e B, marcar A, remover A. Explique a causa antes de mudar qualquer coisa.
2 · Peça a correção e o teste
Corrija e crie um teste com o AppTest do Streamlit que reproduz esses passos, para o bug não voltar.
  • Passos para reproduzir valem mais que "está bugado"
  • "Explique antes de mudar" evita correções no chute
  • Um teste de regressão garante que o bug não volta
  • Para bugs difíceis, o modo Debug coleta evidência rodando o app
O código de referência desta aula passou nesse teste: adicionar A e B, marcar A, remover A → B continua não concluída.
