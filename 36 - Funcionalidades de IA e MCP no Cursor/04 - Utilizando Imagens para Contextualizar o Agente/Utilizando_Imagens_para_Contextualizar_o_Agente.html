Utilizando imagens para
contextualizar o agente

Uma imagem vale por parágrafos de explicação: um mockup do design, o print de um bug visual, a tela de um erro ou um diagrama. Nesta aula: como anexar imagens ao chat, quais modelos conseguem lê-las, como escrever o pedido junto com a imagem, como fechar o ciclo com o navegador e quais cuidados tomar.

Conceito01

Por que imagens?

A documentação do Cursor diz que anexar imagens dá contexto visual para trabalho de interface, depuração e implementação de design, sem precisar transcrever nada à mão.

ImagemSubstitui
Mockup do Figma ou desenhoDescrever cores, tamanhos e posições em texto
Print de um bug visualExplicar "o botão está meio torto ali em cima"
Print de erro ou stack traceCopiar a mensagem linha a linha
Diagrama de arquiteturaExplicar como as partes se ligam
A imagem mostra como deve ficar ou o que está errado. O texto diz o que fazer. Os dois juntos dão o melhor resultado.
Texto que dá para copiar (um erro no terminal, por exemplo) continua melhor como texto: use @Terminals ou cole o texto. A imagem brilha no que é visual.
Na prática02

Como anexar

Arrastar e soltar

Arraste o arquivo de imagem do explorador de arquivos do sistema para o campo do chat.

Colar

Ctrl + V (Cmd + V no macOS) cola a imagem da área de transferência, inclusive prints de tela.

Arquivo do projeto

A ferramenta de leitura do agente também lê imagens que estão no projeto: .png, .jpg, .gif, .webp e .svg. Basta citar o arquivo.

macOSCmd + Ctrl + Shift + 4 captura uma área direto para a área de transferência
Linux (GNOME)Print Screen abre a ferramenta de captura; o print fica copiado e salvo em Imagens › Capturas de tela

Modelos04

Quem consegue ver a imagem

A leitura de imagens é feita pelo modelo. A documentação é clara: as imagens entram no contexto da conversa para análise por modelos com visão (vision-capable).

  • Os modelos de ponta atuais costumam aceitar imagem; confira na página do modelo em cursor.com/docs/models
  • Com Auto, o Cursor escolhe o modelo; se a resposta ignorar a imagem, escolha um modelo com visão
  • Se o modelo não suporta imagem, ela não ajuda: o agente vai trabalhar só com o texto
Imagem também é contexto

Cada imagem ocupa tokens na janela de contexto, como um arquivo. Anexe as imagens que importam, recortadas no que interessa, em vez de prints da tela inteira.

Teste simples: anexe a imagem e pergunte "descreva o que você vê nesta imagem". Se a descrição bater, o modelo está lendo.

Técnica06

O pedido que acompanha a imagem

  • Diga o que a imagem é: "mockup aprovado", "print do bug", "erro ao salvar"
  • Diga o que fazer: criar, corrigir, comparar, explicar
  • Diga onde: arquivo, componente ou página, de preferência com @
  • Diga o que não pode mudar: "sem biblioteca nova", "sem mexer no desktop"
  • Aponte detalhes: "o espaço entre os campos", "o ícone do canto"
Fraco
Faz igual a imagem.
Forte
Este é o mockup aprovado da tela de cadastro. Crie em @src/pages/Cadastro.tsx com os mesmos textos, cores e espaçamentos. Use os componentes de @src/components/ui. Não instale bibliotecas novas. No fim, descreva o que ficou diferente do mockup.
Pedir para o agente apontar as diferenças no final ajuda a revisar o resultado.

Outras fontes08

Imagens que o agente gera e recebe

O agente também gera imagens

A ferramenta de geração de imagens cria imagens a partir de texto ou de imagens de referência: mockups de interface, imagens para o produto, diagramas de arquitetura. Elas são salvas por padrão na pasta assets/ do projeto e aparecem no chat.

Gere um ícone simples de lista de tarefas, fundo transparente, para usar no cabeçalho do app.
Servidores MCP podem devolver imagens

Um servidor MCP pode responder com imagens (screenshots, diagramas) em base64. O Cursor anexa a imagem ao chat e, se o modelo tiver visão, analisa. É assim que ferramentas de navegador e de design mostram o que estão vendo.

MCP é o tema das aulas 05 a 09.
Cuidados09

Antes de colar o print

Dados sensíveis: prints vão para o provedor do modelo como parte do pedido. Corte ou borre senhas, tokens, dados de clientes, e-mails e números de documentos.
Legibilidade: texto pequeno ou borrado vira chute. Recorte a área que importa e use zoom antes do print.
Contexto: cada imagem ocupa espaço na janela. Várias imagens grandes numa conversa longa enchem o contexto mais rápido.
Detalhes finos: medidas exatas em pixels e cores exatas podem sair aproximadas. Quando importam, informe os valores no texto (por exemplo, #E0663A).
Regra prática: imagem para o que é visual, texto para o que é exato. Mockup + valores de cor e espaçamento no pedido é a melhor combinação.
Exercício10

Do desenho à tela

1
Desenhe à mão (ou num editor simples) uma tela com título, dois campos e um botão. Fotografe ou faça um print.
2
Numa pasta nova, cole a imagem no chat e peça uma página HTML igual ao desenho, com o pedido "forte" da seção 06.
3
Abra a página no navegador, tire um print e cole no chat: "compare com o desenho e ajuste".
4
Repita com um print de um bug que você mesmo criar (um botão fora do lugar).
Repare quanto texto você deixou de escrever e quantas idas e vindas foram precisas até a tela ficar igual.
Se o modelo ignorar a imagem, troque para um modelo com visão e repita o teste da seção 04.

3. Onde ficam, por padrão, as imagens geradas pelo agente?

A) Na pasta assets/ do projeto
B) No .cursor/
C) Só no chat, sem arquivo

4. Qual é o cuidado mais importante antes de colar um print?
