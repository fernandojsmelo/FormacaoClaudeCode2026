Código03

Do formulário ao Markdown

"""Monta o currículo em Markdown (prévia) e em PDF (download)."""
from fpdf import FPDF

SECOES = [("resumo", "Resumo"), ("experiencias", "Experiência"), ("formacao", "Formação")]


def linhas(texto):
    """Uma entrada por linha, sem linhas vazias."""
    return [l.strip() for l in texto.splitlines() if l.strip()]


def habilidades(texto):
    return [h.strip() for h in texto.split(",") if h.strip()]


def para_markdown(dados):
    partes = [f"# {dados['nome']}"]
    contato = " · ".join(v for v in (dados["email"], dados["telefone"], dados["cidade"]) if v)
    if contato:
        partes.append(contato)
    if dados["resumo"].strip():
        partes.append("## Resumo\n" + dados["resumo"].strip())
    for chave, titulo in SECOES[1:]:
        itens = linhas(dados[chave])
        if itens:
            partes.append(f"## {titulo}\n" + "\n".join(f"- {i}" for i in itens))
    lista = habilidades(dados["habilidades"])
    if lista:
        partes.append("## Habilidades\n" + ", ".join(lista))
    return "\n\n".join(partes)
  • linhas() e habilidades() transformam texto livre em listas, ignorando linhas e itens vazios
  • Seção vazia não aparece (sem "Formação" em branco)
  • O contato junta só o que foi preenchido, separado por " · "
  • # e ## viram títulos na prévia; - vira lista
O st.markdown não executa HTML por padrão: um texto colado com tags aparece como texto, não vira código na página.
Código04

O PDF com fpdf2

def para_pdf(dados):
    pdf = FPDF(format="A4")
    pdf.set_margins(18, 18, 18)
    pdf.add_page()

    pdf.set_font("Helvetica", "B", 22)
    pdf.cell(0, 11, _latin1(dados["nome"]), new_x="LMARGIN", new_y="NEXT")
    contato = " | ".join(v for v in (dados["email"], dados["telefone"], dados["cidade"]) if v)
    pdf.set_font("Helvetica", "", 10)
    pdf.set_text_color(90, 90, 90)
    pdf.cell(0, 6, _latin1(contato), new_x="LMARGIN", new_y="NEXT")
    pdf.set_text_color(0, 0, 0)

    def titulo(texto):
        pdf.ln(4)
        pdf.set_font("Helvetica", "B", 12)
        pdf.set_text_color(200, 90, 50)
        pdf.cell(0, 7, _latin1(texto.upper()), new_x="LMARGIN", new_y="NEXT")
        pdf.set_draw_color(220, 200, 190)
        pdf.line(pdf.l_margin, pdf.get_y(), pdf.w - pdf.r_margin, pdf.get_y())
        pdf.ln(2)
        pdf.set_text_color(0, 0, 0)
        pdf.set_font("Helvetica", "", 10.5)

    if dados["resumo"].strip():
        titulo("Resumo")
        pdf.multi_cell(0, 5.5, _latin1(dados["resumo"].strip()), new_x="LMARGIN", new_y="NEXT")
    for chave, nome in SECOES[1:]:
        itens = linhas(dados[chave])
        if itens:
            titulo(nome)
            for item in itens:
                pdf.multi_cell(0, 5.5, _latin1(f"- {item}"), new_x="LMARGIN", new_y="NEXT")
    lista = habilidades(dados["habilidades"])
    if lista:
        titulo("Habilidades")
        pdf.multi_cell(0, 5.5, _latin1(", ".join(lista)), new_x="LMARGIN", new_y="NEXT")

    return bytes(pdf.output())
  • A4 com margens de 18 mm
  • cell: uma linha; multi_cell: texto que quebra em várias
  • titulo() desenha cada seção: maiúsculas, cor e uma linha embaixo
  • bytes(pdf.output()) devolve o PDF pronto para o botão
Repare no new_x="LMARGIN", new_y="NEXT" em todo multi_cell. Sem ele, o PDF quebra (próxima seção).
Erro05

"Not enough horizontal space"

Na primeira versão do código de referência, gerar o PDF terminava assim:

fpdf.errors.FPDFException: Not enough horizontal
space to render a single character
1
Depois de um multi_cell, o fpdf2 deixa o cursor à direita do texto, por padrão.
2
O próximo multi_cell(0, …) usa "o resto da linha", que agora é zero.
3
Não cabe nem um caractere: exceção.
Correção: mandar o cursor para a margem esquerda da linha seguinte depois de cada bloco:
pdf.multi_cell(0, 5.5, texto,
               new_x="LMARGIN", new_y="NEXT")
Ao gerar o PDF aparece este erro: [cole o erro completo]. Explique a causa no fpdf2 e corrija em todos os multi_cell, não só no primeiro.
"Em todos, não só no primeiro": o agente às vezes corrige só a linha do erro, e o próximo multi_cell quebra do mesmo jeito.
Caracteres06

Acentos, travessões e emojis

def _latin1(texto):
    # As fontes padrão do PDF só têm caracteres latinos (acentos do português incluídos).
    return texto.replace("•", "-").replace("–", "-").replace("—", "-").encode("latin-1", "replace").decode("latin-1")

As fontes padrão do PDF (Helvetica, Times, Courier) só têm o alfabeto Latin-1. Acentos do português (á, ç, õ) estão lá; travessão, aspas curvas e emojis não.

EntradaNo PDF
São Paulo, ação, vocêIgual
2024–atual (travessão)2024-atual
Emoji 🚀, aspas “curvas”Viram ?, sem erro
Quer tudo, até emoji?

Use uma fonte Unicode (arquivo .ttf, como DejaVu ou Noto Sans) com pdf.add_font(...). Aí o PDF aceita qualquer caractere que a fonte tenha. A fonte precisa ir junto com o projeto.

O código de referência foi testado com acentos, travessão, aspas curvas e emoji: o PDF sai sempre, sem exceção.
