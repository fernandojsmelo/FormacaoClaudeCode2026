Código03

A regra em jogo.py

"""Regras do Pedra, Papel e Tesoura."""
import random

OPCOES = ["Pedra", "Papel", "Tesoura"]
# Quem cada opção vence.
VENCE = {"Pedra": "Tesoura", "Papel": "Pedra", "Tesoura": "Papel"}


def jogada_do_computador():
    return random.choice(OPCOES)


def resultado(jogador, computador):
    """Devolve 'vitoria', 'derrota' ou 'empate' do ponto de vista do jogador."""
    if jogador == computador:
        return "empate"
    return "vitoria" if VENCE[jogador] == computador else "derrota"
  • VENCE diz quem cada opção derrota: uma tabela no lugar de vários if
  • random.choice sorteia uma das três opções
  • resultado() não sabe nada de tela: só recebe duas jogadas e devolve uma palavra
Com a tabela VENCE, uma variante como "Pedra, Papel, Tesoura, Lagarto, Spock" vira só mais linhas no dicionário, com uma lista de quem cada um vence.
Código04

A tela em app.py

import streamlit as st

from jogo import OPCOES, jogada_do_computador, resultado

st.set_page_config(page_title="Pedra, Papel e Tesoura", page_icon="✊")
st.title("✊ ✋ ✌️ Pedra, Papel e Tesoura")
st.write("Escolha sua jogada. O computador escolhe ao mesmo tempo, ao acaso.")

EMOJI = {"Pedra": "✊", "Papel": "✋", "Tesoura": "✌️"}

colunas = st.columns(3)
escolha = None
for coluna, opcao in zip(colunas, OPCOES):
    if coluna.button(f"{EMOJI[opcao]} {opcao}", width="stretch"):
        escolha = opcao

if escolha:
    computador = jogada_do_computador()
    st.write(f"Você: **{EMOJI[escolha]} {escolha}** · Computador: **{EMOJI[computador]} {computador}**")
    final = resultado(escolha, computador)
    if final == "vitoria":
        st.success("Você venceu! 🎉")
    elif final == "derrota":
        st.error("O computador venceu.")
    else:
        st.info("Empate!")
  • st.columns(3) põe os botões lado a lado
  • Botão do Streamlit devolve True só na execução do clique
  • A jogada do computador é sorteada depois do clique, nunca antes
  • Três cores de mensagem para os três resultados
Repare: ao clicar em qualquer outro lugar, o resultado some, porque o botão só vale naquela execução. A aula 14 resolve isso guardando a rodada na sessão.

Teste da regra (pytest)
from itertools import product
from jogo import OPCOES, resultado

ESPERADO = {("Pedra", "Tesoura"): "vitoria",
            ("Papel", "Pedra"): "vitoria",
            ("Tesoura", "Papel"): "vitoria"}

def test_todas_as_combinacoes():
    for j, c in product(OPCOES, repeat=2):
        if j == c:
            assert resultado(j, c) == "empate"
        elif (j, c) in ESPERADO:
            assert resultado(j, c) == "vitoria"
        else:
            assert resultado(j, c) == "derrota"
Rodar: pip install pytest e pytest. O agente pode criar e rodar isso para você.
Testes07

Testando o que é aleatório

Como testar a tela se o computador joga ao acaso? Controlando a sorte: no teste, a escolha aleatória é substituída por um valor fixo.

from unittest import mock
from streamlit.testing.v1 import AppTest

def test_pedra_vence_tesoura():
    at = AppTest.from_file("app.py").run()
    with mock.patch("random.choice", return_value="Tesoura"):
        at.button[0].click().run()   # botão Pedra
    assert "venceu" in at.success[0].value
  • mock.patch troca random.choice só dentro do with
  • O AppTest clica no botão sem abrir o navegador
  • O teste fica repetível: sempre o mesmo resultado
Peça assim ao agente: "crie um teste da tela que fixa a jogada do computador com mock e confere a mensagem de vitória, derrota e empate".
Testes que dependem da sorte passam umas vezes e falham outras. Isso é pior do que não ter teste.
