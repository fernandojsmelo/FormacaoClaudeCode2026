Conceito01

O que é um template

Segundo a documentação, o Agent Builder oferece templates "para padrões comuns de workflow": você começa por um deles para ver como os nós trabalham juntos, ou começa do zero. Um template é um workflow pronto, com nós, ligações, instruções e esquemas já preenchidos.

Canvas em branco (aulas 02 e 03)Template (esta aula)
Ponto de partidaSó o nó StartUm fluxo completo, com vários nós ligados
Bom paraEntender cada peça desde o inícioVer um padrão funcionando e copiar a estrutura
EsforçoVocê escreve todas as instruçõesVocê revisa e troca as instruções de exemplo
RiscoEsquecer uma peça (por exemplo, um guardrail)Publicar com textos e respostas de exemplo que não são do seu negócio
Pense no template como uma aula pronta de arquitetura: o valor está em ver quais nós foram escolhidos e em que ordem. O conteúdo das instruções quase sempre precisa ser reescrito.

Por que rodar antes de mudar

Se algo quebrar depois da sua edição, você sabe que foi a edição, e não o template. É a mesma regra da aula 03: um fator por vez.

Não clique em Publish enquanto o fluxo tiver textos de exemplo. Uma versão publicada pode ser usada no ChatKit e pela API, e responderia aos seus alunos com políticas que não são as suas.

Nó por nó05

Primeiro, o guardrail

O primeiro nó depois do Start é um Guardrails. A documentação o descreve como um monitor de entradas indesejadas, que funciona como passa/não passa: ele testa a saída do nó anterior e você define o que acontece em cada caso.

VerificaçãoO que procura
JailbreakTentativas de fazer o agente ignorar as regras no template
PIIDados pessoais (CPF, e-mail, telefone…)
ModeraçãoConteúdo ofensivo ou impróprio
AlucinaçãoResposta sem apoio nos documentos do vector store
Quando falha

A documentação recomenda encerrar o workflow ou voltar ao passo anterior com um lembrete de uso seguro. No template, a falha leva a um End com uma mensagem curta.

O que dá para ajustar

Cada verificação usa um modelo próprio e um limiar de confiança. Limiar mais baixo bloqueia mais (e erra mais para o lado da cautela); mais alto deixa passar mais.

Guardrail reduz o risco, não zera. As regras dentro das instruções de cada agente continuam necessárias.
Nó por nó06

O Classification agent

É um nó Agent comum, com uma única tarefa: dizer qual é o tipo de pedido. Ele não responde ao cliente. A saída é um JSON com esquema, exatamente como o Avaliador da aula 02.

CategoriaExemplo de mensagem
return_item"Quero devolver o produto"
cancel_subscription"Quero cancelar minha assinatura"
get_information"Qual é o prazo de entrega?"
Deixe o histórico da conversa ligado: muitas vezes o pedido aparece dividido em duas ou três mensagens.
// Output format: JSON · esquema da classificação { "type": "object", "properties": { "classification": { "type": "string", "enum": [ "return_item", "cancel_subscription", "get_information" ] } }, "required": ["classification"], "additionalProperties": false }
O enum é o segredo: o modelo só pode devolver uma das três palavras. Sem ele, viriam variações ("devolução", "Return") que o If/else não reconheceria.
Nó por nó07

O If/else e a linguagem CEL

O If/else não usa IA: ele lê a saída do classificador e escolhe o caminho com expressões em CEL (Common Expression Language). A documentação descreve justamente esse uso: decidir o que fazer com uma entrada que já foi classificada.

RamoExpressão CELVai para
Ifinput.output_parsed.classification == "return_item"Return agent
Else ifinput.output_parsed.classification == "cancel_subscription"Retention agent
Else ifinput.output_parsed.classification == "get_information"Information agent
Else(nenhuma condição bateu)End
input

A saída do nó imediatamente anterior, aqui o classificador.

output_parsed

O JSON já lido, com os campos do esquema.

Previsível

A mesma classificação sempre leva ao mesmo caminho. A IA decide o rótulo; a regra decide a rota.

Nó por nó08

Os três especialistas

AgenteTarefaRecursosDepois dele
Return agentEntender a devolução e propor o que fazerInstruções e saída estruturadaUser approval e, então, End com a resposta
Retention agentEvitar o cancelamento: pergunta o plano e o motivo, e oferece uma alternativaUma ferramenta de exemplo, get_retention_offersEnd
Information agentResponder dúvidas gerais sobre a empresaInstruções com as políticas de exemploGuardrail de alucinação
Um agente, uma tarefa (aula 01). Cada especialista tem instruções curtas e focadas, em vez de um agente gigante que tenta resolver tudo.
Para criar uma nova categoria, você mexe em três lugares: o enum do classificador, uma condição no If/else e um novo agente.
Nó por nó09

Uma pessoa no meio do caminho

O nó User approval (na documentação, Human approval) pausa o workflow e pede uma decisão humana. A documentação o recomenda para fluxos em que o agente prepara um trabalho que merece revisão antes de sair, como enviar um e-mail.

1 · ClassificadorRotula como return_item.
2 · Return agentMonta o pedido de devolução.
3 · ApprovalPergunta: "Posso registrar esta devolução?"
4 · AprovadoSegue para o próximo passo.
5 · EndConfirma ao cliente, ou diz que o pedido foi recusado.
Quem aprova

Quem está do outro lado do chat. Para aprovação por um atendente, a decisão precisa sair do workflow (por exemplo, abrir um chamado) e voltar depois.

Onde vale a pena

Toda ação que muda algo de verdade: dinheiro, cadastro, envio de mensagens. Para responder dúvidas, não precisa.

Atenção10

O que no template é de mentira

A devolução não acontece. O Return agent diz que o pedido está em andamento, mas nenhuma ferramenta registra nada. Sem um MCP ou ferramenta ligada ao seu sistema, é só texto.
A oferta de retenção é fixa. A ferramenta get_retention_offers é um exemplo; as instruções mandam oferecer um desconto inventado. Nenhum sistema real é consultado.
As políticas são de uma empresa fictícia. Prazos, horários e regras do Information agent precisam ser trocados pelos seus, ou vir de um vector store (aula 03).
O guardrail de alucinação precisa de base. Ele compara a resposta com os documentos de um vector store: sem os seus documentos, a checagem não protege nada.
Regra prática: antes de publicar, procure em cada nó por números, nomes, prazos e promessas. Tudo o que o template "sabe" sobre a empresa é inventado.

As novas instruções

Instructions · Classificador Classifique a mensagem do aluno da Formação Claude Code 2026 em UMA categoria: - reembolso: pedir o dinheiro de volta - cancelamento: encerrar a matrícula ou a assinatura - duvida: perguntas sobre aulas, ferramentas e conteúdo Na dúvida entre cancelamento e reembolso, escolha reembolso. Não responda ao aluno. Saída: JSON com "classification".
Instructions · Reembolso Você recebe pedidos de reembolso da Formação Claude Code 2026. - Pergunte a data da compra e o motivo, se o aluno não informou. - Explique que o pedido será analisado; NUNCA confirme o reembolso por conta própria. - Não peça dados de cartão ou senhas. Resuma o pedido em até 4 linhas para a etapa de aprovação.
Repare na regra de desempate do classificador: quando duas categorias são possíveis, diga qual vence. E troque o enum do esquema e as três expressões do If/else para as novas palavras, senão nenhum ramo vai bater.

Depois de 30/1114

O mesmo padrão no Agents SDK

# pip install openai-agents (e OPENAI_API_KEY no ambiente) from typing import Literal from pydantic import BaseModel from agents import Agent, Runner, FileSearchTool class Classe(BaseModel): classification: Literal["reembolso", "cancelamento", "duvida"] classificador = Agent(name="Classificador", instructions="Classifique em reembolso, cancelamento ou duvida.", output_type=Classe) reembolso = Agent(name="Reembolso", instructions="...") retencao = Agent(name="Retenção", instructions="...") tutor = Agent(name="Tutor", instructions="...", tools=[FileSearchTool(vector_store_ids=["vs_..."])]) ROTAS = {"reembolso": reembolso, "cancelamento": retencao, "duvida": tutor} async def atender(msg: str) -> str: c = (await Runner.run(classificador, msg)).final_output agente = ROTAS[c.classification] # o If/else r = (await Runner.run(agente, msg)).final_output if agente is reembolso and input("Aprovar? (s/n) ") != "s": return "Pedido encaminhado para análise." # User approval return r
Correspondência
  • Esquema com enum → output_type com Literal
  • If/else em CEL → um dicionário (ou if) em Python
  • User approval → uma confirmação no seu código ou na sua interface
  • Guardrails → os guardrails de entrada do SDK, que rodam antes do agente
Para levar o template inteiro, use Code → Agents SDK no topo do canvas e copie a exportação em Python ou TypeScript. A documentação avisa: a exportação não garante que todo comportamento se transfira igual. Teste de novo.
Armadilhas15

Erros comuns com templates

Publicar o template como veio. Políticas, ofertas e prazos de exemplo viram respostas para clientes de verdade.
Achar que a ação aconteceu. "Sua devolução foi registrada" sem ferramenta conectada é uma promessa falsa.
Trocar as categorias só no classificador. O enum e as expressões do If/else também precisam mudar, senão tudo cai no Else.
Remover o guardrail "porque atrapalha". Ajuste o limiar e teste; tirar a proteção da entrada abre a porta para jailbreak.
Editar tudo de uma vez. Rode o template original, depois mude um nó por vez e repita os testes.
Copiar sem entender. O valor do template é a arquitetura. Se você não sabe por que um nó está ali, ainda não terminou de estudá-lo.
