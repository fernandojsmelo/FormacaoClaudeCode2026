Conhecendo o
Agent Builder da OpenAI

O Agent Builder é um canvas visual em que você monta agentes arrastando e ligando blocos: um agente que classifica o pedido, uma regra que decide o caminho, uma busca em documentos, uma trava de segurança, uma aprovação humana. Nesta aula, conhecemos a tela, os tipos de blocos e o caminho do rascunho até o produto. E começamos por um aviso que muda a forma de estudar: a OpenAI anunciou que o Agent Builder sai do ar em 30 de novembro de 2026.

Os dois caminhos indicados pela OpenAI

Agents SDK, para quem quer o agente em código, rodando na própria aplicação. Workspace Agents do ChatGPT, para quem prefere montar agentes em linguagem natural e compartilhar com a equipe (planos Business, Enterprise e Edu).

Por que estudar mesmo assim? Os conceitos do módulo (nós, estado, ramificação, RAG, guardrails, aprovação humana, MCP, widgets) são os mesmos do Agents SDK e do ChatKit. E o botão Code exporta o workflow como código do Agents SDK, a porta de saída que usaremos no fim.
O que é02

Agentes, workflows e um canvas

Um agente é um modelo com instruções, ferramentas e um objetivo. Um workflow é a combinação de agentes, ferramentas e lógica de controle que resolve uma tarefa de ponta a ponta. O Agent Builder desenha esse workflow como um fluxograma que funciona.

1 · DesenharNo canvas, você insere e liga nós: quem responde, com que ferramenta, em que ordem, sob que condição.
2 · PublicarO workflow vira um objeto com ID e versões. Cada publicação é uma foto do fluxo.
3 · ImplantarVocê usa o ID num chat embutido com ChatKit ou exporta o código do Agents SDK para rodar onde quiser.
Visual, mas não "sem regras"

Cada ligação entre nós é uma aresta tipada: o nó seguinte sabe exatamente que dados vai receber.

Para quem

Desenvolvedores e especialistas no mesmo lugar: quem entende o negócio lê o fluxo sem ler código.

Quanto custa

O Agent Builder não tem preço próprio: você paga o uso dos modelos e ferramentas, pelos preços normais da API.

O exemplo da documentação

Um "ajudante de lição de casa" usa um agente para reescrever a pergunta, outro para classificá-la (resposta direta ou pesquisa) e agentes especializados para cada tipo. Cada um com escopo pequeno e claro.

Agentes pequenos erram menos, são mais fáceis de testar e podem usar modelos mais baratos. O classificador da tela da página 04 só responde um JSON com a intenção.
Um agente gigante que "faz tudo" é o erro mais comum de quem começa: quando algo dá errado, ninguém sabe em que parte.
Dados entre nós07

Ligações tipadas e variáveis

O contrato entre os passos

Clique num nó para ver suas entradas e saídas. O Agent Builder mostra o contrato de dados entre os passos e garante que o nó seguinte receba as propriedades que espera.

Variáveis

input_as_text é o texto que a pessoa digitou. Saídas de agentes viram variáveis para os próximos nós, e o Set state cria variáveis globais.

Condições em CEL

If/else e While usam a Common Expression Language, uma linguagem curta de expressões. Por exemplo: a intenção classificada é "return"? Vai para o agente de devoluções.

Saída em JSON com esquema (um campo intent que só aceita "return", "cancel" ou "question") torna a ramificação confiável. Com texto livre, o If/else vira adivinhação.

Uma regra de segurança do ChatKit

Ao criar a sessão, o servidor precisa enviar um identificador único por usuário, depois de autenticá-lo. A chave da OpenAI fica no servidor; o navegador recebe só um segredo temporário da sessão.

A exportação não garante comportamento idêntico: fluxos muito determinísticos, conexões e permissões precisam ser revistos e testados de novo.
Segurança10

Os dois riscos de todo agente

Injeção de prompt

Texto não confiável (uma mensagem, um arquivo, uma página) traz instruções escondidas que tentam passar por cima das suas. Objetivo comum: fazer o agente vazar dados por uma ferramenta, ou agir fora do combinado.

Vazamento de dados privados

Sem ataque nenhum, o modelo pode mandar a uma ferramenta MCP mais dados do que o usuário esperava. Guardrails ajudam, mas você não controla tudo o que o modelo decide compartilhar.

  • Não coloque variáveis não confiáveis nas instruções do desenvolvedor; passe-as como mensagem do usuário
  • Use saídas estruturadas entre os nós (enum, esquema fixo)
  • Dê instruções claras, com exemplos do que não fazer
  • Mantenha a aprovação ligada nas ferramentas MCP, para leitura e escrita
  • Use guardrails na entrada: dados pessoais e jailbreak
Mesmo com tudo isso, agentes podem ser enganados. Dê a eles só o acesso de que precisam.

Armadilhas12

Erros comuns de quem começa

Construir um produto novo sobre o Agent Builder hoje. Em 30/11 ele para. Para produção, use o código exportado.
Texto do usuário nas instruções do agente. Dá ao atacante o nível mais alto de controle. Passe como mensagem.
Um agente para tudo. Difícil de testar, de corrigir e de baratear.
Ramificar com texto livre. Sem saída estruturada, o If/else erra por uma vírgula.
Pular o Preview. Ele mostra cada nó executando; é onde os erros aparecem baratos.
Desligar a aprovação no MCP. Uma instrução escondida vira um e-mail enviado sem ninguém ver.

Recapitulando

Um canvas para agentes,
com data de validade

O Agent Builder monta workflows de agentes num canvas: nós de Core, Tools, Logic e Data, ligações tipadas, variáveis e condições em CEL. Você testa no Preview, publica versões e implanta com ChatKit ou exportando o código do Agents SDK. Anunciado para sair do ar em 30 de novembro de 2026, ele ainda é um ótimo jeito de ver como um agente funciona. Os conceitos continuam no Agents SDK, a porta de saída que o módulo vai usar.
